# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

Until `1.0.0`, this project does not follow SemVer. Every release increments only the patch (`0.0.1 → 0.0.2 → 0.0.3 …`). Any release can break the surface language, the CLI, or the JSON shapes; entries below don't separately flag "breaking" because the assumption is "anything might be". The narrower contract that does hold: within a single version, all first-party tooling — `awsum`, `awsum-vscode`, `awsum-zed`, `tree-sitter-awsum` — ships from the same version number and is mutually compatible. SemVer kicks in at `1.0.0`.

## [Unreleased]

### Added

- **`awsum lsp` now has an automated test suite (`Awsum.LspSpec`).** Two layers: unit tests driving the extracted request logic directly (formatting edits, diagnostics, document symbols, code actions, workspace symbols, the version-mismatch check, and `initializationOptions` parsing), and an in-process end-to-end layer that spins up a real server over a pipe pair via `lsp-test` and exercises initialize / didOpen / formatting / documentSymbol / hover / codeAction / pushed diagnostics — confirming the handlers are wired and the JSON-RPC envelopes are shaped the way the five editor clients depend on.
- **`Simplify` is switchable off for the compiler's own tests, gated three ways.** A library-level `SimplifyOff` (no `awsum` CLI flag) lets the suite assert `runtime(simplify(core)) == runtime(core)` with the runtime as oracle: `just test-no-simplify` (whole successful corpus vs the committed stdout goldens), `just test-property` (every generated input through both pipeline modes), and `awsum-bench --snapshot` (one no-simplify run per backend against the stdout anchor).
- **`awsum-bench --snapshot` / `just benchmark-snapshot`: median-benchmark golden files.** Runs each `test/sources/benchmark/` program N times per backend (default 5) and writes a per-backend `median (min–max)` of wall time + peak RSS to `.benchmarks/<NAME>/bench.txt` — outside `.snapshots/`, so a snapshot reset can't take the medians with it. Each run's stdout is cross-checked against a backend-agnostic anchor; a deviating or failed run renders `mismatch` / `timeout` / `fail` and exits non-zero. No threshold, not part of `just test`/CI; macOS-only.
- **Benchmark programs now have committed compiler snapshots.** `just test` golden-tests `.snapshots/benchmark/<NAME>/compiler/` (AST, Core, symbols, per-backend codegen text, lifetime analysis) for every benchmark program, minus the runtime outputs — so a `bench.txt` delta is diagnosable from the committed IR diff.
- **Test harness: a 60-second ceiling on every backend run and harness compile.** A diverging program or a non-terminating compiler pass now fails its item by name instead of hanging the suite; runtime output groups are nested under their program's name.
- **Lambda parameters accept a type annotation: `\(n : T) -> …`.** The annotation supplies the parameter type in synthesis position — a `let`-bound lambda, or one passed to a polymorphic higher-order function — where no expected type flows in and body-driven constraints are not threaded back into the arrow. It is the only inline way to pin a lambda's input without spelling out its whole arrow, result row included (`let f = \(n : Int32) -> addInt32 n n` infers the `Either (UnderflowError | OverflowError) Int32` result), and it pins a higher-order callee's type variable so a sibling bare literal is checked against it (`apply (\(n : Int32) -> …) 5`). In check position, where the parameter type is already known, the annotation is verified against it — a disagreement is a dedicated error pointing at the annotation. Top-level definition parameters do **not** take annotations (their type comes from the mandatory signature); the inner pattern must be a simple binder, not an ascribed destructure. Pinned by `syntax_lambda-param-annotation` and `syntax_lambda-param-annotation-pins-hof`. (The vestigial `LambdaInSynthesisPosition` typechecker error — unreachable since lambdas gained a synthesis form, and whose message now described exactly what the annotation provides — was removed in passing.)
- **`let` bindings accept the type signature on its own line: `n : T` then `n = e`.** The signature may sit on a separate line directly above the definition — the same shape as a top-level definition, and what Haskell / Elm developers reach for — alongside the existing inline `let n : T = e`. Both forms are accepted everywhere a `let` binding appears (standalone `let … in` and `do`-block `let`), and `awsum format` preserves whichever was written rather than normalising, since neither is canonical. Constraints: the signature must sit directly above its definition naming the same binder — no blank line and no other binding between, so an orphaned signature and a doubly-ascribed binding are dedicated parse errors — and the own-line form is for a single binder (`PVar`) only (a destructuring binding has no signature line). In a multi-binding `let`, the formatter fences an own-line-signature binding with a blank line on each side while single-line bindings pack together. Pinned by `syntax_let-ownline-signature`, `syntax_let-multibinding-fenced`, `syntax_do-let-ownline`, the two `not-supported_let-ownline-*` error snapshots, and the render∘parse round-trip properties (which now generate both layouts).

### Changed

- **`awsum build -t llvm` / `-t wasm`: a binder forwarded through a self-tail-call is moved into the next iteration, not copied-then-dropped.** When a tail loop's recursive call (`CContinue`) forwards a borrowed `CVar` whose binder is dropped at that step and is linear (occurs once across the call's arguments), the reference-counted backends emitted a redundant `__inc_ref` — the next-iteration slot taking its own reference — paired with the binder's `__free_recursive`: two ops per iteration that cancel. The `CContinue` emitter now recognises the move — the loop-back-edge analogue of the value-tail `CVar` carve-out already there — and skips both, donating the binder's existing reference to the destination slot, while keeping the load-bearing extract-inc that protects it from the dying scrutinee's cascade-free. For an unboxed `Int32` loop variable that is two near-no-op calls removed per iteration; for a boxed one (a `List` / `Tree` threaded through a loop) it is a real refcount load-add-store plus free-check removed from every iteration of the hot loop. The `CDrop` stays in Core — `Awsum.Lifetime` keeps its total, uniform death-annotation and codegen realises the move — so the managed backends (JVM/CLR/JS, no refcount header) are untouched. Program output is unchanged — identical stdout across all five backends still holds, and no runtime golden moved; the effect is purely fewer refcount ops in every hot loop (~5,000 lines of pure removal across the `compiled.*.ll` corpus). Pinned by `recursion_case-in-continue-arg` and `recursion_continue-param-swap` under the cross-backend identical-stdout, property (both pipeline modes), and no-simplify suites.
- **JS output (`awsum build -t js`): a `let` in expression position lowers to a hoisted `const`, not a per-evaluation IIFE.** A `CLet` reached by the expression lowerer was emitted as `((x) => body)(rhs)` — a closure allocation plus call on every evaluation, 502 of them across the corpus. It now bubbles to `const x = rhs;` on the nearest enclosing statement spine (a `return`, a `const` initialiser, a case scrutinee, a `CCall` argument or `CCon` field whose earlier siblings are variables/literals), keeping the `let`'s own already-unique binder so no temp name is invented. Evaluation order is preserved: a binding floats only past siblings whose residual is a variable or literal (immune to reordering); past a call, a field read, or an in-place reuse — and in a `CContinue` parallel rebind, where an effectful or reuse argument must not move — the `let` keeps a single wrapper IIFE instead. Program output is unchanged — identical stdout across all five backends still holds, and no runtime snapshot moved; the effect is fewer closures and more legible JS (the corpus's 502 expression-position let-IIFEs drop to zero). Exercised by the regenerated `compiled.js` corpus under the cross-backend identical-stdout, property (both pipeline modes), and no-simplify suites.
- **`max_stack` / `max_locals` (JVM), `.locals` (CLR), and the WASM `.locals` vector are derived from the emitted instruction stream, not predicted by a second traversal over Core.** Each backend declared its verifier/validator limits from a sizing pass that walked the source IR in lockstep with the emitter — a parallel computation obliged to mirror every emission decision, which would silently under-declare on any program shape the test corpus didn't contain (a `VerifyError` / `ClassFormatError` / invalid-module on a user program, all snapshots green). The limits now come from the instructions a method actually emits: JVM gains `maxStackOf` (abstract interpretation over `[JvmInstr]` — per-instruction stack deltas, branch-target depths, dead code after `goto` / `areturn` / `return`) and `maxLocalsOf` (highest slot touched plus every StackMapTable frame's breadth); CLR gains the matching `maxLocalsOf` over `[CilInstr]` (its `maxStackOf` was already stream-derived); WASM's nine per-purpose local "bands" — each based at a predicted offset, so a mispredicted band could silently overlap the next and corrupt a slot — collapse into a single `ecNextLocal` counter threaded functionally through emission (sibling scopes reuse), with the `.locals` count read back via `maxLocalsOf`. The JVM additionally derives the limits for its hand-written prelude-helper methods — the last hand-maintained sizing — so one path feeds both the Jasmin text and the classfile bytes for every method, and the verifier validates the full per-instruction stack-effect table (long arithmetic, `dup2`) on every run rather than only the subset user code emits. Removed in the process: the JVM `CContinue` `n+1` and `CLoop` `2` stack floors and three "must mirror" obligations, six WASM Core sizing traversals, and the CLR/JVM Core locals predictors. Behaviour-neutral — every backend still produces identical stdout, and the declared limits only tighten toward the exact peak (no program's were too low). Pinned by the whole corpus run on each backend's real verifier/validator across the snapshot, property (both pipeline modes), and no-simplify suites.
- **`Awsum.Cps` and `Awsum.Tco` reject the nodes a later pass mints uniformly, instead of silently passing some through.** Both run before `Awsum.Simplify`, so their input never carries `CLet` / `CProj` / `CJoin` / `CJump` (nor the post-`Tco` `CLoop` / `CContinue` / `CDrop` / `CReuse`). Three policies had coexisted on that one class of node: `Awsum.Cps.goNonTail` waved `CProj` through as a trivial leaf and rejected `CLet` with a message describing a rejected ANF plan; `Awsum.Cps.goTail` and `Awsum.Tco.rewriteTail` leafed every unmatched node through a catch-all — including `CJoin`, whose body may hold a `CContinue` or a tail self-call. All three functions now enumerate every `CExpr` constructor and raise a uniform pipeline-bug `error` on any node a later pass mints. The hazard was latent — the pass order makes those nodes unreachable today — but the silent `CJoin` leaf was a trap: a future re-`Tco` after `Simplify` would leave a tail self-call inside a `CJoin` body as a `CCall` past `Awsum.StackSafety`, i.e. unbounded stack on JVM/JS. Behaviour-neutral: no program reaches the new arms, so no snapshot or runtime golden moved; removing the catch-alls also makes a future `CExpr` node a compile-time obligation in both passes rather than a silent leaf. Pinned by `Awsum.CoreSpec`'s pipeline-node guards.
- **`effectfulIn`'s effectful-built-in set is derived from the `Awsum.BuiltIn` registry, not a hardcoded parallel list.** `Awsum.Core.effectfulIn` — which marks the calls `Awsum.Simplify` must not drop — listed the four `internal*` platform primitives in a string `Set` of its own, parallel to the registry that already declares those names. The registry now carries a per-entry `Pure` / `Effectful` flag as its single source of truth, and `effectfulIn` consults the derived `effectfulBuiltIns`; the "adding a new CLI effect" checklist in `Awsum.Program.Cli` names the flag step. Latent fix: a fifth platform effect added only through that checklist would have bypassed the hardcoded list, and `Simplify` would then legally delete it on every backend (its `case (newEffect s) of Unit -> …` collapses, stdout stays identical, no suite notices). Behaviour-neutral today — the derived set equals the old literal — so no snapshot or runtime golden moved. Pinned by `Awsum.CoreSpec`'s registry-consistency spec.
- **The `CExpr` traversals are consolidated in `Awsum.Core`, resolving the `CDrop` reference-position convention once.** The two `freeVars` copies (in `Awsum.Cps` and `Awsum.ElaborateLower`) and the two name→name renames (`Cps.alphaRename`, `Simplify.renameVarFull`) are now single shared definitions, and a new `children :: CExpr -> [CExpr]` backs the binder-unaware folds (`usedBuiltIns`, `nextFreshConTag`, `usesIntLit`, `effectfulIn`, `reusedBinders`, plus `Simplify`'s `exprSize` / `hasLoopOrContinue`) so a new Core node updates one traversal rather than several in lockstep. The two renames had disagreed on `CDrop`: `alphaRename` treated the dropped name as a binder (rename stopped, the name kept), the correct view — now the only one — is a reference, renamed and descended into like `CReuse`, so a future post-`Lifetime` rename can no longer leave a drop naming a renamed-away cell (a refcount imbalance on LLVM/WASM). Latent today — every rename and `freeVars` runs before drops exist — so behaviour-neutral on every backend: no snapshot or runtime golden moved. Pinned by the new `Awsum.CoreSpec`.
- **The same-arity reuse carve-out's gate is one named predicate (`reuseTargetArm`), and reuse arity-safety gains a regression test.** The `reconstructsSameArity` check that keeps `Awsum.Simplify` from inlining a single-use binder into — or collapsing the dispatch of — an arm that rebuilds a cell of its own arity (the linear-scrutinee shape `Awsum.Reuse` rewrites in place) was duplicated across `inlineArm` and `collapseIdentical`; it now lives in one predicate. `memory_reuse-arity-mismatch` pins that reuse never fires across an arity mismatch (a three-field scrutinee rebuilt as a two-field cell), where reusing the larger cell in place would strand the dropped field's slot — a leak no stdout suite sees. Behaviour-neutral on every backend: no snapshot or runtime golden moved.
- **Structural-row matching in the typechecker is no longer quadratic on ground rows.** `Awsum.HM.unifyRows` / `goMatch` (unification) and `rowSubsume` (the check-mode acceptance relation) matched two N-label structural rows by a nested scan — O(N²), worst-case when the rows list the same labels in opposite order. When neither side carries a free type variable, unification now decides the match by multiset equality of canonical labels (O(N log N)), and subsumption resolves each label by a `Set` lookup, falling back to the structural scan only for the genuinely-subsumed-but-not-equal labels (an inner row that grew, e.g. `Maybe Bool` fitting `Maybe (Bool | Unit)`). Rows carrying free row-variables keep the previous path. No program changes how it compiles — inferred types, acceptance, and diagnostics are identical; only compile time on very wide rows drops (the cost of a 4000-label reversed-row unification falls roughly four-fold). Exercised at width 300 by the new `stress-300_row-reversed-unify` snapshot.
- **`docs/spec/grammar.ebnf` now documents parameter binders accurately.** The `Lambda` and `ParamBinder` productions were stale: `Lambda` listed only bare `LIdent` parameters, and neither admitted the `(p : T)` ascription form — though the parser has accepted `\(n : T) -> …` and `f (x : T) = …` since the parameter type-annotation feature. The `render∘parse` round-trip generator was extended in step, so the lambda-parameter ascription form is now generated (matching the function-definition coverage) and exercised by the parser round-trip and the `tree-sitter-awsum` / `awsum-vscode`-TextMate highlighting property suites.
- **`awsum format -i` leaves an already-canonical file untouched.** When the formatted result equals the file's current contents the write is skipped, so the file's mtime is preserved and editors / watchers / build systems see no change; a real reformat still rewrites the file, and the exit code is success either way.
- **`awsum lsp` document formatting returns minimal per-hunk text edits instead of a whole-document replace.** `textDocument/formatting` now diffs the source against its formatted form (line-level) and sends one `TextEdit` per changed line range — and no edits at all when the document is already canonical — so editors leave untouched regions (folds, cursor position, undo history) alone and an already-formatted buffer is never rewritten. The LSP counterpart to the `awsum format -i` skip-when-unchanged above.
- **New `Awsum.Simplify` Core-to-Core pass (adds the `CLet` / `CProj` / `CJoin` / `CJump` Core nodes).** Runs after `Tco`, before `Lifetime`, to a per-declaration fixpoint, performing: case-of-known-constructor (a case over a literal constructor or row injection collapses to the matching arm); case-over-constant (the same for a scrutinee naming a constant constructor tree, chasing alias chains); case-of-case fusion through join points, and case-of-join above a residual join; single-arm and identical-arms collapse (a dispatch that decides nothing is removed); identity-reconstruction reduction (an arm rebuilding the cell it matched yields the scrutinee); single-use case-arm binder inlined to a `CProj`; non-recursive function inlining with a `let` cleanup family (dead-let, single-use inline, copy-propagation, known-projection); and integer built-in const-folding over literal operands (overflow folds to the same `Left` the runtime helper returns). Every rule is gated so no work is duplicated and no platform-effect call is dropped. Program output is unchanged — identical stdout across all five backends still holds, and no runtime golden moved; the effect is smaller, faster generated code. Pinned by the `caseOfCase` / `constFold` / `fnInline` differential properties and the no-simplify gate above.
- **Cell reuse now reaches inner cells (nested `CReuse`); hot recursive loops stop allocating on LLVM/WASM.** A binder whose sole use is the scrutinee of an inner case has its drop sunk into that case's arms (where `Awsum.Reuse` looks), so the continuation cells of `$scc$`-merged CPS functions become reuse targets: a `mirror`/`reverse`-style loop now rewrites both its argument pack and its data cell in place and allocates nothing. Output unchanged across all five backends.
- **Smaller, more legible generated code on every backend, output unchanged.** A case over a bare variable dispatches in place — the scrutinee-alias copy is gone (around 4,000 fewer lines each of `compiled.js` and `compiled.wat`, ~1,400 of `compiled.j` across the corpus); JS expression-position case-trees share one immediately-invoked arrow instead of one per nesting level; tail-recursive and in-place-reuse rebinds are scheduled like a parallel copy, so temps appear only for genuine cycles; and the JVM no longer null-stores into binder slots no arm extracts.
- **`docs/pipeline.md` now matches the memory passes:** `CReuse` lowers as in-place stores on every backend (LLVM/WASM keep the uniqueness-checked copy-on-write fallback), `CDrop` on the JVM nulls the dropped slot at loop rebinds and returns, and the `Simplify` bullet states the same-arity carve-out's reuse-eligibility boundary.
- **Test fixtures: per-program runtime inputs renamed `stdin/` → `input/`, the default output golden `no-stdin.txt` → `no-input.txt`.** The suite delivers each file as the program's single CLI argument, not over stdin, so the old name lied; the 218 goldens were renamed with content intact.
- **JS output (`awsum build -t js`) renders a single-`return` arrow as an expression body and drops the parens around a lone parameter.** A function or runtime helper whose body is one `return` was emitted as `(x) => { return e; }`; it is now `x => e`, folded onto an indented continuation line when it doesn't fit beside `=>`. Multi-statement bodies stay block-form (`x => { … }`), and the parameter list keeps its parens with zero or two-plus parameters. Program output is unchanged — identical stdout across all five backends still holds, and no runtime snapshot moved; the effect is purely more legible generated JS (the `compiled.js` snapshots shrink).
- **Dead `case` arms whose tag is never constructed on any reachable path are now pruned, computed flow-sensitively.** Lowering's whole-program shake already dropped a `case` arm whose constructor / row tag nothing builds, but it collected the constructable-tag set by a flat textual walk — so a combinator arm that rebuilds the very constructor that gates it kept itself alive, a cycle disconnected from any real source. The set is now the least fixed point of a guarded walk: an arm's constructions count only once the arm's own tag is independently constructed. The dominant case is the IO combinators (`andThenIO` / `handleErrorIO` / `bindIO` / `mapIO` / `mapIOError`), each of which carries arms for `IO.Args.getArgs` and `IO.Stdin.read{AllString,AllBytes}` that rebuild those platform-effect nodes around the threaded continuation: a program importing neither `IO.Args` nor `IO.Stdin` never constructs them, yet the flat walk kept the arms — dragging the per-arity `$apply` dispatcher and every backend's argv / stdin decoder into the output. They are now removed; even hello-world shrinks, because `runIO`'s own unused getArgs / stdin walker arms are pruned. Program output is unchanged — identical stdout across all five backends still holds, and no runtime snapshot moved; the effect is purely smaller generated code (the `prelude_*`, `io_*`, and `row_*` snapshots drop sharply — `prelude_handleErrorIO`'s WAT by ~60%).
- **A row-widening coercion that is the identity on the runtime representation no longer emits a structural deep-copy helper.** Lowering already treated equal types, a `Never` end, and pure within-a-row widening as no-ops; it now also recognises that a coercion through a shared nominal head (or a function arrow) is the identity when every field (or side) coercion is. The dominant case is the IO error-row widening `IO Never X → IO (e | Never) X` that `andThenIO` / `bindIO` / `mapIO` / `mapIOError` / `handleErrorIO` insert on their pure arm: because the IO spine's tags are row-independent and an error label keeps its per-label tag in any wider row, that coercion is the identity — but it used to lower to a full structural deep-copy of the IO value (itself recursive, so CPS-transformed, with defunctionalised continuation wrappers feeding the apply dispatcher). It now lowers to nothing. Program output is unchanged — identical stdout across all five backends still holds, and no runtime snapshot moved; the effect is purely smaller generated code for every program that composes `IO` or `Either` through these combinators (the `prelude_*-row-collapse` snapshots drop by thousands of lines each). A genuine re-tag — a shared label whose inner row grew, e.g. `Maybe Bool → Maybe (Bool | Unit)` — still emits its helper.
- **Lowering now consumes a typed AST (`Awsum.TExpr`) from the typechecker instead of re-inferring types via best-effort `synthLabelType`.** Each definition is elaborated to a `TExpr` carrying the resolved type at every node, with an explicit coercion node at every structural-sum (row) injection, and a new `Awsum.MonomorphizeRows` pass specialises row-polymorphic combinators (`bindEither`, `andThenIO`, …) before lowering. Lowering can no longer disagree with the type the typechecker already knew, closing the residual class of row-injection bugs at the source; ~1000 lines of re-inference machinery are deleted.
- **The surface formatter (`awsum format`) is now built from a `prettyprinter` `Doc`, instead of hand-rolled string concatenation with manual indentation.** Layout is structural, not width-adaptive — a `let` always splits to two lines, `case` is always multi-line, a `|>` chain of three or more links is always multi-line — so formatted output is unchanged and the `parse ∘ render` round-trip and format-idempotency properties still hold. Mechanism cleanup, not a behaviour change.
- **WAT output (`awsum asm -t wasm` and the WASM codegen) is now built from a `prettyprinter` `Doc` projected in one pass**, with each function body indented to reflect `block`/`loop`/`if` nesting (`end` closes a level, `else` sits at the enclosing one) and uniform blank-line spacing between functions, instead of hand-rolled string concatenation with a flat 4-space listing. WAT whitespace is insignificant, so the assembled `.wasm` and program output are unchanged; this is legibility plus codegen coherence (the byte backends already build a typed spec before projecting it).
- **JS output (`awsum build -t js`) is now built from a typed JS AST rendered with `prettyprinter`, instead of hand-rolled string concatenation, and is consistently indented.** Everything in the emitted file — the runtime helpers, the user/prelude declarations, and the IIFE wrapper — flows through the AST, so the previously dense one-line expression-form `case` dispatches (up to ~8.6 KB on a single line) now read as nested blocks. Program output is unchanged — identical stdout across all five backends is verified on every commit; this is legibility plus codegen coherence (the byte backends already build a typed spec before projecting it).
- **LLVM IR output (`awsum build -t llvm`) is now built from a typed LLVM IR rendered by one renderer, instead of hand-rolled string concatenation.** Every part of the emitted module — the C-runtime declarations and module globals, the refcount/allocator runtime, the per-program generated code (including the refcount-elision bookkeeping), and the `main` entry footer — flows through the typed IR, matching the "typed spec, then project" shape the byte backends (`.j`/`.il`/`.wat`) and the JS backend already use. Compiled output is unchanged: `clang` assembles the same binary and identical stdout across all five backends is verified on every commit; the only `.ll` text change is that `phi` operands now render `[ %v, %lbl ]` (consistent with the runtime helpers) rather than `[%v, %lbl]`. Codegen coherence, not a behaviour change.
- **The CLR target now runs under Server GC.** The generated `AwsumMain.runtimeconfig.json` sets `"System.GC.Server": true` (`dotnet` reads it automatically next to the DLL) — emitted identically by `awsum build -t clr`, `awsum run -t clr`, and the test + benchmark harnesses. awsum programs allocate a heap object per Core cell, so Server GC's parallel per-core heaps clear that allocation churn faster than the workstation GC's single heap. Program output is unchanged across all five backends; only CLR GC throughput changes (and the `.benchmarks/` CLR medians, once re-snapshotted).
- **Snapshot test sources normalised to one house style, recorded in `docs/testing.md`.** Every successful-corpus program that threads an `Either` to stdout now uses the same shape — `eitherToIO res |> andThenIO IO.Stdout.print |> handleErrorIO onError`, with `onError` enumerating the error row by constructor — and every doc comment is behaviour-only (no references to compiler modules/passes, other tests, or the property / no-simplify layers). A new `## Test source conventions` section in `docs/testing.md` states the rule; `just format-fix` now also formats the Awsum test sources and `stdlib/Prelude.aww`; and three tests were renamed for grouping (`string_eq` → `strings_eq`, `type-ascription-expression` / `literal-underscore-separator` → `syntax_…`). The property tests were normalised the same way — each `runMain` `Right`/`Left` shim replaced by the system-under-test `property`, a named `onError`, and a canonical `main` pipeline. Program output is unchanged across all five backends — test-corpus and tooling cleanup.
- **Pattern shapes are now validated at nested field positions, not just at the top of a `case`.** The three rules the top level already enforces now apply at every nested field: a constructor pattern needs a sum to match; a `(x : T)` ascription discriminates a structural sum, not a nominal type or primitive; and a wildcard / binder may not catch the remainder of a position a sibling matches specifically. So a partial catch-all (`Just A | Just _`, `Just (n : Int32) | Just _`) is rejected as `PartialCatchAll`; an ascription on a non-row field (`Just (b : Bool)`, where `Bool` is the nominal field type) and a constructor of an unrelated type on a primitive field (`Wrap Nothing` where the field is `Int32`) are rejected at the offending pattern with the same diagnostics the top level gives (`NonConstructorNominalArm` / `Case on non-sum type`). Previously these slipped past the field-position check and reached lowering, where they crashed (`conflicting … in merge`, localised to line 1), miscompiled (an ascription is lowered as a row-tag dispatch, which then reads a non-existent slot — a runtime crash on all five backends), or silently matched the wrong arm. The same judgment now also covers a genuinely-polymorphic field: a constructor or `(x : T)` ascription on a field whose type is a bare type variable (`Box (Just _y)` / `Box (_y : Int32)`, `Box`'s field being the parameter `a`) is rejected (`Case on non-sum type`) — an abstract type has no constructor to match, and lowering the match read a non-existent slot, a runtime miscompile identical on all five backends. And a constructor that names a different type than the one matched is rejected (`ConstructorNotInType`) both at the top level (`Just` on a `T` scrutinee — previously accepted in silence as a dead arm once `A`/`B` already covered `T`, against no-defaulting; gated on a sibling arm corroborating the scrutinee type, so a `do`-block desugared over a non-`Either` keeps its clearer type-mismatch) and at a nested field (`Just True` on a `Maybe T` field — previously a confusing missing-combination witness). The two ignore-the-whole-field forms stay legal (`Just _`, `Tuple2 A _ | Tuple2 B _`), since there the field is ignored uniformly across the arms. Pinned by `case-partial-catch-all-{nested,row}`, `case-field-ascription-{nominal,merge,tyvar}`, `case-field-con-{non-sum,on-tyvar,wrong-type}`, and `case-con-wrong-type`.
- **Typechecker cleanup, output unchanged: the recursive-type set is computed once per `case`, and the pattern-matrix helpers are deduplicated.** `recursiveTypeNames` (the Tarjan SCC over the whole constructor environment that gates coinductive inhabitedness) was rebuilt on every `isConInhabited` / `isTypeInhabited` call — per-constructor inside the matrix-exhaustiveness recursion, so O(arms × constructors × depth) graph rebuilds for one `case`; it is now computed once per `case` and threaded in. The shared column primitives (`isTyVarTy`, the row-head-label and concrete-inhabited-label helpers) that `matrixWitness` and `rejectPartialCatchAll` both walk are hoisted to one module-level copy so the two cannot drift; `mergeAlts` / `mergeRowAlts` share one `groupByTag`; and lowering's duplicate `tyConHead` is replaced by the typechecker's `extractTyCon` (which also handles the `TyEmpty` head the lowering copy silently missed). Diagnostics and program output are unchanged across all five backends.
- **Internal cleanup: the unused `CDropKind` / `BinderKindMap` drop-classification on the Core `CDrop` node is gone.** The node tagged every drop with a three-way `CDropKind` (`DropFreeUnchecked` / `DropFreeStringChecked` / `DropNoop`) backed by a `BinderKindMap` side table — scaffolding for an abandoned "header only on strings" reclamation scheme. Only one tag was ever constructed, every backend ignored the field (reclamation is driven by the runtime cell header, not a static tag), and the `Lifetime.freeVars` export had no importer; all three are removed and `CDrop` now carries just the binder and body. No user-visible effect — generated code and stdout are identical on all five backends; the only change is that the `core.txt` IR dumps no longer print the tag.

### Removed

- **`empty type` may no longer be declared in user code.** The standard library declares the one empty type the language needs — `Never`, the row identity — and because every empty type is interchangeable with it, a user-declared one was only ever an alias of `Never` that looked like a distinct type while being identical. Declaring `empty type X` in user code now gives an error pointing at the real options: `Never` for the row identity, or a plain `type X` for a distinct uninhabited type. The `empty type` form stays the standard library's way of declaring `Never`. Pinned by `empty-type-user-declared`.

### Fixed

- **A structural sum whose only non-empty alternative is `T` — `(Never | T)`, and the same nested in a head (`Maybe (Never | T)`, `Either E (Never | T)`, `List (Never | T)`) — no longer miscompiles when matched with a used binder.** `useIt : (Never | Int32) -> …; useIt val = case val of (n : Int32) -> … n …; main = useIt (42 : Int32)` passed `check` (and `--strict`) but crashed at runtime on every backend: LLVM/WASM memory-faulted, the JVM threw `ClassCastException`, the CLR `InvalidCastException`, JS read `undefined`. A documented-valid program (`docs/type-system.md`: "a `case` on `(Never | A)` need only handle `A`"), it violated identical-results and errors-as-values at once. The cause was a split runtime representation for a single type. `unify` treats `(Never | T) ~ T` (`Never`, the row identity, drops in `Awsum.HM.absorbAndMatch`), so a value flows between the two positions with *no* coercion — which forces them to share a representation: bare, like `T`. But several producers tagged it (`CRow [tag, payload]`): a literal or ascription injected into the row, a function body checked against a `(Never | T)` return. Every consumer, meanwhile, *read* a tag — `Awsum.ElaborateLower` lowered the row `case` (and a nested `Just (n : T)` / `Just (Ctor …)` descent) to a `CRowCase` / `CProj scrut 1`. A value arriving bare via a `unify`-success path — a synthesised call argument, a widened nominal head `Maybe T → Maybe (Never | T)` — then had its (nonexistent) tag read as a payload. The fix makes a single-inhabited row bare *everywhere*: `synthCoerce` / `coercionIsIdentity` / `needsRowCoerce` normalise such a row to its sole non-empty label before any tag is minted (so `Int32 → (Never | Int32)` is the identity, and a bare value widened into a genuinely ≥2-label row is still wrapped once), and the three consumer sites bind the scrutinee directly instead of through a tag — a plain `CVar` scrutinee renaming in place, a compound one lifted into a let-helper. The cut is exactly `TyEmpty`, matching `unify`: a `type Void` (zero-constructor `TyCon`) or `Box Never` is uninhabited but is *not* dropped, so `(Void | Int32)` stays a genuine tagged 2-label row as before. The 4th mechanic of the open-row / `Never` family, after the three fixes above. Pinned by `row_never-single-inhabited` (the `case` consumer, identity passthrough, and bare→tagged widening) and `row_never-single-inhabited-nominal-head` (the nested-pattern consumers under `Maybe` / `Either` / `List`).
- **A row combinator whose result row carries a concrete error label is no longer accepted into `Either Never` / `IO Never`.** `bindEither op1 (\_n -> pureEither 0)` ascribed `Either Never Int32` (and the `IO` analogues — `andThenIO` / `bindIO` / `mapIO` with `pureIO` / `failIO` — ascribed `IO Never …`) passed `check`, though `op1 : Either ErrA Int32` makes the call's type `Either (ErrA | e2) Int32`: the live `Left ErrA` was typed as impossible, the consuming `case` legitimately dropped its `Left` arm, and the value misdispatched at runtime — LLVM/WASM read the error tag as a payload (`24`), the JVM threw `ClassCastException`, the CLR printed `System.Object[]`, JS fell through silently; the `IO` form additionally crashed the `runIO` walker on an `IOFail` arm the type let it prune. It violated identical-results and errors-as-values at once. Two causes, both in the bidirectional `EApp` spine. (1) The spine stamped `expected` onto its result `TApp` without re-checking the threaded result type — its early shape validation ran while the combinator's result-row variables were still free, when `(e1 | e2) ~ Never` legitimately binds both to `Never`, and the operands then pinned `e1` to the concrete `ErrA` with nothing re-validating; a boundary guard now verifies the fully-threaded result subsumes into `expected`. (2) `rowSubsume` (that guard's relation) rejected a degenerate row on the actual side — `(Never | Never) <: Never`, a duplicate `(A | A) <: A` — because its `(_, TyOr)` shortcut ignored the row set-semantics (`Never`-drop, dedup) that `unify` and `canonicalLabel` already honour; it now requires every actual alternative to subsume, accepting the degenerate rows the guard meets on legitimate code (`IO.Stdout.print "a" |> andThenIO …`) while still rejecting the concrete-label-into-`Never` hole. The open-tail widening `(EZ | e) <: (EA | EB | EZ)` is unaffected. Pinned by `row-combinator-result-into-never` and `row-combinator-io-into-never`.
- **A binding can no longer declare a type more polymorphic than its body — closing a general `unsafeCoerce`.** `val : a` accepting `val = (42 : Int32)`, then `useString : String = val`, fed an `Int32` into a `String`: `check` passed, and at runtime JS printed `42` while LLVM read raw bytes — a value of one type used as another, divergent across all five backends, violating identical-results and errors-as-values at once. It was not value-specific (`g : Int32 -> a; g _x = 42`, used at `String`, broke the same way) nor top-level-specific (`let x : a = (42 : Int32) in …`, and the `do`-block `let`, had the identical hole). The cause: a binding's body was reconciled with its declared type by ordinary unification (`Awsum.Typing.unifyOrSubsume` / `elabLet`), where the declared type's variables are *flexible* — so `unify a Int32` simply bound `a := Int32` and the concrete body satisfied the polymorphic claim; the value was then generalised back to the signature and usable at any type. Each binding's body is now additionally checked against its signature with every signature type variable replaced by a fresh **rigid skolem** (a `TyCon` that unifies only with itself): a body that fixes such a variable to a concrete type, or conflates two distinct ones (`f : a -> b; f x = x`), no longer typechecks (`SignatureTooPolymorphic`). The check is additive — the authoritative elaboration is still the original (flexible) one, so every accepted program compiles to byte-identical output and no snapshot moved; only previously-miscompiling programs are newly rejected. Legitimate polymorphism is untouched: a body as general as its signature (`identity x = x`, the prelude's `bindEither` injecting an `e1`-typed value into `(e1 | e2)`) passes, since a skolem matches itself — the whole prelude and test corpus still compile. This also subsumes the structural-sum case `val : (a | b) = (42 : Int32)` (a concrete value injected into a free-tyvar row alternative, which mis-tagged the cell by the variable's name and diverged when later closed and matched): every path that built such a value went through a polymorphic binding, all now rejected. Pinned by `signature-too-polymorphic-{value,fn,row,let}`.
- **A `case` on a structural sum whose label set still carries a free type variable (an open row tail, `(Int32 | r)`) is now rejected instead of miscompiling.** The tail `r` is the caller's to pick via implicit injection, so a value of any type the caller chooses (`f (True : Bool)`) reached a `CRowCase` with no arm for its tag — and that arm-less dispatch behaved differently on every backend: LLVM/WASM/JS read the wrong cell field as the matched type, JVM threw an uncaught `ClassCastException`, CLR printed the raw object. It violated both cardinal invariants at once — identical results on every target, and errors-as-values / no runtime crashes — a full `unsafeCoerce` (`toInt (True : Bool)` feeding `addInt32` gave `2` on LLVM/WASM, `11` on JS, a crash on JVM/CLR). The exhaustiveness checker excused the tail from coverage in two places — `caseArmsRow` (a row scrutinee) waved a `TyVar` label through as "no obligation", and the matrix path (`matrixWitness`, for an open tail nested in a matched constructor field like `Maybe (Int32 | r)`) filtered tyvar labels out of the set a `case` must cover — and a `(rest : r)` arm ascribing the tail was wrongly accepted as a backdoor cover, though a type variable has no runtime tag and a `CRowCase` has no catch-all arm. Matching an open row cannot be made exhaustive without a catch-all, which the language forbids by design, so it is now a compile error (`MatchOnOpenRow`) naming the open row and asking the user to close it — fired before arm processing on a row scrutinee (closing the `(rest : r)` backdoor too) and surfaced through the matrix witness for a nested tail. The same rule covers a row whose alternatives are *themselves* free type variables (`(a | b)`) — any tyvar label is uncoverable — while a wildcard field that *absorbs* such a row without dispatching on it (`Just _` over `Maybe (Int32 | r)`) stays exhaustive, since no tag is read. The injection side is unchanged: an open tail remains a valid extension slot for *building* a row (a bare `Nothing` still routes to the unique concrete `Maybe T` label, `bindEither` / `bindIO` still widen error rows), so the only programs newly rejected are those that *match* a tail the caller controls. Pinned by `row-match-open-tail{,-nested,-arm}`, `row-match-tyvar-alternative`, the row-absorbing `row_open-tail-absorb`, and the reworked `row_open-tail-inject` (which now closes the tail before matching).
- **A non-tail recursion whose post-call work returns a multi-constructor type (`Either`, any row) no longer leaks its CPS continuation chain on LLVM/WASM.** Stack-safety lowers such a recursion to a heap continuation chain (`$cps$f` / `$apply$f`); each continuation cell should be freed as `$apply` consumes it on the way back up. It was — but only on the arm that reuses the cell. `Awsum.Reuse` plants an in-place `CReuse` by stripping the single `CDrop scrut` that `Awsum.Lifetime` places over the matched-cell scope, on the premise that an enclosed same-arity `CCon` reuses the cell instead of freeing it. When that scope held a `case` that splits — `$apply`'s post-call work is `succInt32 r`, whose `Right` (success) arm forwards the result while only the `Left` (overflow) arm rebuilds a cell — the strip removed the drop from *both* arms but reinstated it (as `CReuse`) on only the rebuilding one, so the success arm freed the continuation cell *never*: one leaked cell per recursion step. A single such recursion masked it (the chain dies at process exit); any repeat (a loop, or two sequential calls) accumulated linearly — `descend 2_000_000` repeated 25× peaked at 1533 MiB instead of a flat 63. Reference-counted backends only; JVM/CLR/JS reclaim the unreachable chain through their GC. It violated the memory guarantee (`docs/memory-management.md`: every heap cell reclaimed once unreachable, on every backend) on exactly the backends that have no GC to fall back on, and could OOM at scale. The fix: in `Awsum.Reuse.rewriteFirstCCon`, a sibling `case` arm that does not receive the `CReuse` re-acquires the stripped `CDrop scrut`, restoring the free the strip removed (the reusing arm keeps it absorbed into its `CReuse`). The pre-existing `recursion_countdown-uint8` and `closures_over-application-row-combinator` programs carried this shape and were silently leaking; their regenerated LLVM/WASM snapshots each gain exactly one `__free_recursive`. Pinned by `Awsum.CoreSpec`'s `insertReuse` regression (a split scope must drop the scrut on the non-reuse arm, and must not double-drop when every arm reuses) and exercised end-to-end by the new `recursion-no-tree` benchmark, whose three deep recursion shapes hold peak memory flat across repeats.
- **A type constructor named in a data-constructor field is now resolved against the program's type names, exactly as a signature is.** `type Phantom = Phantom Nonexistent` typechecked as `OK` and ran to completion — a never-constructed such constructor surfaced nowhere, a used one only as a confusing use-site mismatch — while the same `Nonexistent` in a signature was correctly caught as `Unknown type constructor`. The field-validation path (`Awsum.Typing.validateTypeParams`) walked only `TyVar` nodes and waved every `TyCon` through; it now runs the same `wellFormedTypeWith` resolution the signature path uses, so a field's type-constructor head — bare, applied, or nested inside a known type (`Maybe Bogus`) — must resolve (`UnknownTypeCon`), and a `_`-prefixed one is rejected (`ReferencingIgnored`), closing the underscore-convention leak where `_T` in a field (lexed as a `TyCon`, not a `TyVar`) slipped through. Relatedly, a type *parameter* named `_` then an uppercase letter (`type Foo _T = …`) is now rejected (`UppercaseTypeParameter`): such a name lexes as a type constructor in any use position, so the parameter could never be referenced as a type variable in a field. Against "No invisible decisions". Pinned by `field-unknown-type-con`, `field-unknown-type-con-nested`, `field-ignored-type-con`, and `type-param-uppercase`.
- **A type constructor is now applied to exactly its declared number of arguments, everywhere a type is written.** `Maybe Int32 Int32` (one too many), `Either Int32` (one too few), a bare unsaturated `Maybe`, `IO Int32` — all typechecked. The signature form surfaced only later as a confusing `expected Maybe Int32 Int32, got Maybe a` far from the declaration (or, for an unused definition, as nothing); the constructor-field form (`type T = T (Maybe Int32 Int32)`) and — worst — the row-alternative form (`(Maybe Int32 Int32 | String)`, when no value inhabited the ill-arity alternative) were accepted silently and *ran to completion* identically on all five backends. The validator (`Awsum.Typing.wellFormedTypeWith`) checked only that a type constructor's *name* was known; its carrier was a name-only `Set`, with no arity to check against. It now consults a `Map` from every type constructor in scope — the built-in primitives plus each declared type, keyed by its parameter count (`IO` arrives with arity 2 from the prelude's `type IO e a`, not a hardcoded literal) — and an application spine whose head resolves to a constructor must supply exactly that many arguments, else `TypeConArityMismatch` (`expects N argument(s), got M`) at the constructor head. The one validator runs on both signatures and constructor fields, the same path as the name-resolution fix above, so the two are held to one standard. A type-*variable* head (`a Int32`, higher-kinded use) is left to unification as before — this closes the arity gap, not kinds. Against "No invisible decisions". Pinned by `type-con-arity-{too-many,field,too-few}`.
- **A constructor pattern that binds the wrong number of fields is now rejected, at every pattern position.** `Single a b c` for a one-field `Single`, or `Tuple3 a` for a three-field constructor, was silently accepted — the `zip`-based field walks in the typechecker truncated, so surplus binders vanished unbound (a later use then read as `Unknown variable`) and a too-short pattern surfaced as a confusing `no arm matches Tuple3 _ _ _` non-exhaustiveness witness instead of the real error. A purely structural arity check (`checkPatternArity`) now runs at each pattern entry point — nominal `case` arm, structural-sum arm, nested field, and `let` destructuring (parameter and `do`-bind destructuring reach it through their `case` desugaring) — raising `PatternArityMismatch` (`expected N fields, got M`) before any binder is created, so it precedes the shadow / shape / matrix-exhaustiveness checks. Against "No invisible decisions". Pinned by `pattern-arity-{too-many,too-few,nested,let,row}`.
- **An empty type (`Never`) named in a type annotation inside a function body now resolves to the row identity, like the same name in a signature.** The pass that rewrites `Never` to the empty/row-identity type ran over signatures and constructor fields but not the annotations a function body carries — an ascription `(e : … Never …)`, a `let n : … Never … = …`, a lambda parameter. There `Never` stayed an ordinary nominal type and failed to unify with the empty-type `Never` a signature uses: `main = (IO.Stdout.print "x" : IO Never Unit)` was rejected against `main : IO Never Unit` with a baffling `expected IO Never Unit, got IO Never Unit` (identical when rendered — one side a `TyEmpty`, the other a `TyCon`). The rewrite now descends into function bodies. Pinned by `rows_never-in-body-annotation`.
- **The unifier treats an empty type (`Never`) as the row identity when two rows of different width meet (`Awsum.HM.unifyRows` / `absorbAndMatch`).** `unify (Never | A) A` rejected the pair — `Never` was counted as an unabsorbable extra label — though `(Never | A)` is the same row as `A`. Empties are now dropped from the width comparison, while still serving as the target a tyvar absorbs, so `Never ~ (e1 | e2)` still binds both `e1` and `e2` to `Never` (the IO/`Either` composition shape `IO (Never | e2) b ~ IO Never Unit`). Not reachable from surface `.aww` — the typechecker's acceptance boundary is `rowSubsume`, which already handled empties — so pinned at the unifier level by `Awsum.HMSpec` rather than a program snapshot.
- **Injecting a value into a structural sum with two same-head alternatives (`(Maybe T | Maybe U)`) no longer routes it to the wrong one.** When the injected value's constructor left its type argument unpinned — `Nothing`, a partially-applied `Left` / `Right`, any nullary or partial constructor — both alternatives matched by head, and the value silently took the *first* alternative's row tag: `(Nothing : Maybe U)` dispatched to the `Maybe T` arm, identically wrong on all five backends (invisible to cross-target equivalence). Two causes, both closed in the typechecker. (1) Check-mode dropped the substitution that pinned the value's type, so an ascription's `(… : Maybe U)` never reached the elaborated tree and the later coercion saw a free variable; check-mode now pushes that substitution into the value — restricted to row-free unification, since unifying rows assigns row variables greedily and forcing that choice would mis-specialise `MonomorphizeRows`. (2) A genuinely-ambiguous injection with no pin (a bare `Nothing` into `(Maybe T | Maybe U)`) was silently accepted; it is now rejected as `AmbiguousRowInjection`, asking for an annotation (no-defaulting). A constructor that pins its argument (`Just C`) and a row with one head-compatible alternative (`Nothing` into `(Maybe T | Int32)`) are unaffected — and an open tyvar tail does not count as a competing alternative (it is an extension slot resolved per-call-site, mirroring an abstract-row source), so a bare constructor into `(Maybe T | r)` routes to the unique concrete label rather than being falsely flagged. Pinned by `row_same-head-ascription`, `row-inject-ambiguous-same-head`, and `row_open-tail-inject`.
- **A `case` over a multi-field constructor no longer accepts an uncovered combination of fields.** Exhaustiveness checked each field column independently, so `Tuple2 A A | Tuple2 B B` was treated as total even though `Tuple2 A B` and `Tuple2 B A` match no arm — at runtime the uncovered value silently fell through to a neighbouring arm, identically wrong on all five backends (the property-suite failure mode "all backends agree but the answer is wrong"). Column coverage is not cartesian-product coverage for any constructor with ≥2 fields. The check is now matrix-based (Maranget usefulness / specialization): after fixing the first field, the residual matrix keeps only arms consistent on it, so an uncovered combination is caught. It composes through structural-sum scrutinees, row-typed constructor fields, and arbitrary row↔nominal nesting; a hole is reported as one concrete uncovered value — `no arm matches Tuple2 A B`, `Right Nothing`, `Wrap (Pair True False)` — via the new `NonExhaustiveMatch` diagnostic, while a wholly-absent top-level constructor / row label keeps the existing `missing […]` list. An uninhabited row alternative imposes no coverage obligation, mirroring the existing skip for an uninhabited nominal constructor — a `case` over `(Never2 | Int32)` matched only by its `Int32` alternative is total, and so is one over `(Maybe (Box Never) | Int32)` matched only by `Nothing` and `(i : Int32)` (the `Just (Box Never)` constructor of the nominal alternative carries an uninhabited field, so it too is skipped, as on a `Maybe (Box Never)` nominal scrutinee). Pinned by `case-non-exhaustive-fields{,-partial,-row,-row-field,-deep}`, `adt_fields-exhaustive`, `adt_fields-uninhabited-row-label`, and `row_uninhabited-nominal-label`; the two existing nested-exhaustiveness snapshots (`case-non-exhaustive-nested`, `pattern-do-bind-refutable`) now show the witness form.
- **A non-constructor pattern in a `case` on a nominal type now points at the pattern, not at line 1.** A `(x : T)` ascription pattern, a bare-variable arm, or a `let (x : T) = e` over a nominal scrutinee was rejected by a span-less internal error that localised to `1:1` (the first `import`). It now carries the offending pattern's span and explains that nominal types are matched by constructors while `(x : T)` discriminates a structural sum. Pinned by `not-supported_nominal-case-ascription` and `not-supported_let-pattern-ascription`.
- **`awsum format` (to stdout) no longer appends a trailing blank line — its output is byte-identical to what `awsum format -i` writes to disk.** The stdout path printed with `putTextLn` over a string `formatSource` already terminates with `\n`, so it emitted `…\n\n` while `-i` wrote `…\n`; `awsum format f | diff - f` then flagged a spurious difference on an already-canonical file. Stdout now writes the formatted text verbatim.
- **`awsum format` no longer wedges a blank line between every line of a multi-line top-level comment.** A run of source-adjacent top-level comments — e.g. a commented-out definition — parses as one `CommentDecl` per line, and the blank-line block separator was applied between each; the formatter now groups a run of comments with no blank line between them into a single block. A blank line in the source still breaks the run, so an author's paragraph break between two comment blocks survives (and a doubled blank line collapses to one, as everywhere else). Pinned by `top-level-comment-blocks` and the regenerated `improperly-formatted-source`.
- **A nested chain of the same row-polymorphic combinator no longer rejects a well-typed destructuring continuation.** `eitherToIO pair |> andThenIO (\(Tuple2 a b) -> …) |> andThenIO (\holds -> …)` failed with `Type mismatch: expected Either e2 (Tuple2 Int32 Int32), got …` — the destructuring step's result was checked against its *input* type. The bidirectional spine left the polymorphic head's scheme variables un-freshened, so two nested `andThenIO` (or `bindEither`, …) applications shared the names `a`/`b`/`e1`/`e2`, and the inner step's input binding leaked into the outer step's result element. The synthesis path was immune (it resolves bottom-up), but a destructuring continuation can't be synthesised and falls to the spine; a named downstream consumer masked the bug by pinning the result first. The spine now freshens the head's instantiated type per call site. Pinned by `rows_io-andthenio-destructure-continuation`.
- **In-place cell reuse no longer mutates a cell a later sibling still reads.** A `CContinue` re-staging the matched cell beside a same-arity rebuild (`MyCons _h t -> loop f2 (MyCons 7 t) xs`) passed the reuse gate, so the in-place store clobbered the cell the later argument re-staged — LLVM/WASM printed `7` where JVM/CLR/JS printed `1` (reproduced on released `awsum` 0.0.6). The gate now blocks the rewrite when any later-evaluated sibling mentions the scrutinee. Pinned by `memory_reuse-continue-restage`.
- **Cell reuse no longer corrupts a structure the caller retains — `CReuse` carries uniqueness evidence (`ReuseMode`).** A scrut drop kills only the local reference, so a callee overwrote a structure the caller still held (`let ys = reverse xs`) without a refcount check — four backends printed `2e` where LLVM printed `22`. Reuse now mutates compiler-minted pack/continuation cells (`ReuseUnique`) unconditionally, and user-visible data (`ReuseGuarded`) on LLVM/WASM only under a `rc == 1` check with copy-on-write (a plain allocation on the managed backends, which have no refcount header). Pinned by `memory_reuse-shared-retained` and the `tree_sum_repeat` anchors.
- **LLVM/WASM: an expression-position `case` whose arms return bare variables no longer triggers a use-after-free.** `f (case b of True -> x; False -> y)` stored the value without the refcount increment a call boundary provides, and the scope-end decrement then freed a cell the consumer still held. Both backends now increment at every expression-position arm tail whose value is a borrow (move-aware, looking through `let`).
- **JVM: a multi-arm `case` in a constructor-cell field or in a tail-call argument no longer crashes the compiler.** `IO.Stdout.print (case x of …)` and a tail call with a case argument emitted StackMapTable frames declaring an empty operand stack while the half-built cell / sibling arguments were still on it; such fields and continue arguments now evaluate into save locals first. Branch-free shapes keep the inline emission, so existing JVM output is byte-identical.
- **WASM: a `case` buried in a constructor-cell field no longer overlaps the scrutinee slot with the bound-vars region.** The case-probe behind the slot reservation did not look inside `CCon` / `CRow` / `CReuse` fields, so `IO.Stdout.print (case p of MkPair a b -> …)` clobbered the second binder's slot; the probe now descends into cell fields.
- **JVM, CLR, and WASM: a deep `case` in scrutinee position no longer overflows the locals table or fails bytecode verification.** Locals sizing ignored the scrutinee's own slot demand, and the StackMapTable typing broke when one slot index served different roles in different subtrees; sizing now takes the scrutinee/arms maximum and frame typing is contextual.
- **JVM: a tail-recursive rebind that drains a dropped binder over its parked arguments no longer fails bytecode verification.** The declared `max_stack` ignored the `aconst_null` the pending-drop drain pushes on top of the parked arguments, so a three-argument parameter swap was rejected with `VerifyError: Operand stack overflow`; the bound now floors at `n + 1`. Pinned by `recursion_continue-param-swap`.
- **A local binder sharing a bare name with a top-level declaration no longer miscompiles.** Naming a `bindIO` continuation `cont` — the same name the prelude binds for the `IOGetArgs` continuation inside `bindIO` — made defunctionalisation resolve the prelude's local `cont` to the user's top-level `cont`, drop the continuation's captures, and emit a dangling closure; `runIO` then called a non-function and every backend failed (`v_cont is not a function` on JS, a runtime trap on LLVM, a hang on the JVM). Cross-module shadowing is legal — a binder in one module may share a name with a top-level in another — so the closure passes' practice of resolving a bare reference against the global declaration table was the bug. A new lowering pass renames any local binder colliding with a top-level name (to a `$`-tagged fresh name user source can't spell) before those passes run, restoring the invariant they assume. The collision is independent of rows, `IO`, and nesting: it bit any prelude combinator whose parameter or pattern variable (`cont`, `k`, `io`, `next`, …) matched a user top-level.
- **Over-applying a higher-order function now compiles to working code on every backend instead of crashing the compiler.** `identity applyOnce inc 5` — applying `identity` (arity 1) to more arguments than it takes, so the surplus applies to its *result* — aborted lowering with an internal `Map.!` error: defunctionalisation scanned every argument for a function value, including those past the callee's arity, and placed a parameter-slot index beyond the callee's parameter list. Arguments beyond a callee's arity are now split off as an over-application of its result and routed through the closure-apply dispatcher, which is generalised to handle under-application too — a closure given fewer arguments than its remaining arity grows into a larger closure at runtime (the defunctionalised equivalent of a partial application) rather than only saturating. Covers a computed closure that is then under-applied (`let g = identity applyOnce inc in g 7`), repeated growth, and the row-combinator form (`identity (bindEither oa) cont`); identical stdout across all five backends holds.
- **JS backend: a NUL (`\0`) immediately followed by a decimal digit in a string literal no longer emits invalid JavaScript.** The NUL was written as `\0`, so `\0` plus a digit formed a legacy octal escape — a `SyntaxError` under `"use strict"` that made the program fail to run on the JS target while every other backend printed the bytes. NUL is now emitted as a fixed-length Unicode escape (U+0000). The U+2028 / U+2029 line- and paragraph-separator code points get the same fixed-length-escape treatment: they are legal raw inside an ES2019+ string literal (so not a live bug on the supported Node floor), but escaping them keeps the emitted `.js` valid even if it is later re-parsed under pre-ES2019 rules.

- **Widening a structural sum where a shared label's inner row grows now re-tags correctly.** A value bound at `(Maybe Bool | A)` and used where `(Maybe (Bool | Unit) | A)` is expected kept the narrower label's runtime tag, so the consuming `case` matched the wrong arm (LLVM/JVM) or read `undefined` (JS). The coercion now dispatches on the value's label and re-tags any whose structure changed; pure widening — where every existing label keeps its tag — stays a no-op.
- **Sequencing a platform effect with `bindIO` and a failing continuation now tags the error correctly.** `bindIO IO.Args.getArgs k` (and the `IO.Stdin.readAll*` forms) routes through a partially-applied prelude helper that row-monomorphisation skipped, so the continuation's error reached the handler untagged and every backend crashed. Partial applications of row-widening combinators are now specialised too.
- **An alias whose body is a partial application now compiles to working code on every backend.** `greet = const "hi"` (and similar `f = combinator arg` aliases) was eta-expanded into a nested call that became an un-dispatchable closure, producing a crashing or invalid artifact. The eta parameters are now appended to the inner call instead.
- **A row combinator partially applied and bound to a named value with a concrete continuation row now compiles to working code on every backend.** `partialB = bindEither oa` declared `(Int32 -> Either EB Int32) -> Either (EA | EB) Int32` left the combinator's result-row variable abstract on the call head — the concrete row lives only in the binding's signature — so row monomorphisation skipped it, the generic body's `Left`-payload coercion stayed an identity, and the continuation's error reached the consuming `case` with its nominal tag instead of the row tag (out-of-bounds on LLVM/JVM/CLR/WASM, wrong value on JS). Row monomorphisation now threads each definition's declared signature through its body as the checking-mode expected type and recovers the concrete row from it, specialising the partial application.
- **A row combinator applied to an inline continuation now resolves its error row from the surrounding signature, so the continuation's own injections are tagged and the call head specialises.** A combinator like `bindEither` / `bindIO` / `andThenEither` whose continuation is written inline — a lambda, or a `do`-block such as `bindEither oa (\_n -> do …)` — left that continuation's result row an abstract variable: its `Left` / `failIO` injections recorded no coercion (a label does not inject into a bare variable) and reached lowering untagged, while the call head never specialised, so the injected error hit the consuming `case` mis-tagged and the backends disagreed (wrong arm / out-of-bounds / `undefined`). The checker now pins that row before elaborating the continuation: the operand pins the combinator's input-side variable, and the result-side variable is solved as the signature's full error row. Because the bound is the whole row rather than a positional or set-difference slice, acceptance no longer depends on the order the labels are written in the signature, holds whether the continuation is the last argument (`bindEither oa cont`) or the first (`oa |> andThenEither cont`), composes through nesting (`bindEither a (\_n -> bindEither b cont)`) — including when an operand is itself row-polymorphic and pins no concrete label (`bindEither (pureEither n) cont`), where the continuation's still-free row variable is pinned to the full signature row once every operand has been checked — and through a label shared between the operand and the continuation, and covers the `IO` path (`bindIO IO.Args.getArgs cont`) as well as `Either`.
- **A row combinator whose continuation injection is reached through an argument position or a nested named continuation now tags correctly.** Two shapes survived the inline-continuation fix with an untagged `Left`: a combinator call passed as an argument to another function (`identity (bindEither oa (\_n -> Left EB))`), and a combinator with a named continuation and a `pure`-like operand nested inside another continuation (`bindEither oa (\n -> bindEither (pureEither n) inner)`). Both were synthesised without the surrounding concrete row, so the injected error reached the consuming `case` mis-tagged — a crash on LLVM/JVM/CLR/WASM, a wrong value on JS. The checker now redoes any application whose synthesised result still carries a variable the expected type pins (routing the nested call through the bidirectional spine), and the spine applies a final upper-bound pin from the signature after every argument is checked, so a `pure`-operand's free row variable is concretised and the call head specialises.
- **A lambda that applies a captured function-typed parameter now compiles to working code on every backend.** `poly k = applyOnce (\n -> k n) 5` — where the function-typed parameter `k` is captured by an inline lambda that then flows into another higher-order function — dropped `k` when `poly` was defunctionalised: the specialised copy left `k` as a free variable and its per-arity closure dispatcher had no case, so every backend crashed (a dangling reference on JS). A function-typed parameter used as a value (captured, not called) is now resolved to its closure representation, so it reaches the dispatcher like any other closure. The bug reproduces without rows; the row-typed form (`bindEither oa (\n -> k n)`) is fixed by the same change.
- **A function whose result row is partially concrete with an open tail, used where the row widens by two or more labels, compiles correctly.** `zeroOr : Int32 -> Either (EZ | e) Int32` used at `Either (EA | EB | EZ) Int32` aborted row monomorphisation with a compiler invariant error: the bidirectional spine pinned the tail `e` to the whole expected row, making the call head's instantiated row un-expressible as a substitution instance of its declared scheme (one declared row variable cannot absorb two-or-more labels). The spine now leaves a result-only row variable — one that occurs only in the result, never in a parameter, i.e. a genuinely-polymorphic output tail rather than a combinator's input-side variable — free; the concrete label keeps its tag and every backend agrees. Plain-variable pinning of a partial combinator's residual row variable against a concrete signature (`let pb : (Int32 -> Either EB Int32) -> … = bindEither oa`) is unaffected.
- **An unannotated `let` binding a partially-applied row combinator is rejected with a clear diagnostic instead of miscompiling.** `let pb = bindEither oa in pb cont` binds `pb` polymorphically (it can be used at several error rows), but Awsum resolves rows per call-site with no runtime row evidence, so a single shared closure over a partial combinator cannot be specialised — its injection previously reached the consuming `case` untagged and the backends disagreed. The typechecker now reports it (`Cannot monomorphise let-binding 'pb': its type has a row variable in a parameter position …`) and points at the annotation that fixes it (`let pb : T = …`); a genuinely-polymorphic output tail (`let f = zeroOr`), a single-variable error row (`let m = mapLeft oa`), and a non-row polymorphic value (`let id = \x -> x`) are unaffected.
- **`awsum format` no longer produces source that fails to parse when a wide character precedes a nested `let`'s bindings.** The parser measures indentation in display width (Megaparsec counts a wide East-Asian character as two columns), but the renderer aligned the bindings of a nested own-line-signature `let` by code-point count — so a wide character (CJK, emoji, …) earlier on the `let` line left the continuation lines one column short of the first binding, and the re-parse rejected the formatted file. The renderer now measures layout width the parser's way (a shared `Awsum.Width.displayWidth` over Megaparsec's own `isWideChar`), so `parse ∘ render` holds for any Unicode; all-narrow output is byte-identical. The `render ∘ parse` round-trip and format-idempotency generators no longer restrict string and comment content to ASCII, so they now exercise wide and supplementary characters.
- **`awsum lsp` reports positions in UTF-16 code units (as LSP mandates), not display-width columns.** Diagnostics, hover ranges, document- and workspace-symbol locations, and code-action edits shipped the parser's display-width column straight to the client, so on any line with a wide (CJK, …) or narrow supplementary-plane (mathematical bold letters, …) character before the position the squiggle / hover target / rename edit landed on the wrong column in all five editor clients — and an incoming hover cursor (UTF-16 from the client) was compared against display-width spans. Positions now convert against the source line at the protocol boundary in both directions (sharing `Awsum.Width`; the format-on-save edit path already did this). Pinned by `Awsum.LspSpec`.
- **A `case` over a multi-field constructor matched by field combination no longer miscompiles.** Two lowering bugs in the arm merge, both on well-typed programs: a constructor with a row first field followed by a further discriminating field (`W2 (Int32 | String) T`, arms `W2 (n : Int32) A | … B | …`) produced a row-case with two arms of the *same* row tag — the second-field dispatch was dropped, so LLVM printed nothing while JVM/CLR/WASM/JS took the first arm, breaking the five-backend identity on a correct program; and merging arms that bind a shared field to different names (`W (Wrap a) A | W (Wrap b) B`) kept only the first arm's binder, so the other arms' bodies referenced an unbound name (empty on every backend). Row-case arms now merge recursively like nominal ones (`mergeRowAlts`), and arms whose binders differ are alpha-renamed onto a fresh canonical list before the union. Pinned by `adt_fields-row-then-nominal` and `adt_fields-merge-binders`.
- **A constructor pattern that descends into a row-typed field's label now lowers correctly.** A field of structural-sum type matched by a constructor of one of its labels — `Wrap IY`, where the field is `(Inner | Int32)` and `IY : Inner` — was lowered as a bare `CCase` on the constructor tag, which reads the field's *row* tag instead: a miscompile when every arm descended, and a `conflicting pattern shapes in merge` compiler error the moment a sibling arm ascribed another label (`Wrap (i : Int32)`), rejecting a valid exhaustive program. The pattern now dispatches on the row tag first and on the constructor second (mirroring the row-case path), under the field binder a sibling ascription arm shares, so mixed-depth matches — `Wrap IY | Wrap IN | Wrap (i : Int32)` — compile and run identically on all five backends. Pinned by `adt_fields-row-label-descend`.
- **A duplicate `case` arm that ascribes a field to the same row alternative is reported as unreachable, not an internal error.** Two arms matching the same constructor and ascribing one field to the same label — `Wrap (a : Int32) -> … | Wrap (b : Int32) -> …` — are the same shape and so the second is unreachable, but the unreachable-arm check compared patterns structurally with no `PAscribe` case, so it missed them; they then reached lowering's arm-merge, which has no representation for two same-tag arms with non-dispatching bodies and bailed with `conflicting pattern shapes in merge` localised to line 1. The check now compares ascriptions (same label, inner patterns coincide), so the case is reported as `Unreachable case` at the offending arm. Pinned by `case-duplicate-ascription`.
- **A non-regular (nested) recursive type no longer hangs the compiler (and `awsum lsp`).** A `case` over a constructor whose field involves a recursive type whose type argument grows each level — `type Rec a = MkRec (Rec (Maybe a))`, or the Okasaki nested datatype `type Nest a = NestCons a (Nest (Tuple2 a a)) | NestNil` — drove the inhabitedness check into unbounded recursion: its cycle guard keyed on the full type structure, which never repeats once the argument keeps growing, so `awsum check` / `build` / `run` spun forever (and `awsum lsp`, which re-typechecks on each edit, hung the editor). Whether it hung even depended on constructor order — a base constructor listed first was rescued by short-circuit evaluation, the recursive one first was not. The guard now keys on the head type-constructor *name*, restricted to genuinely recursive type constructors (those that reach themselves through their fields), so it terminates for any constructor order while still walking non-recursive nestings like `Box (Box (Box Never))` to their leaf — finite uninhabitedness detection is unchanged, as is the coinductive reading that a recursive type is inhabited. Pinned by `adt_nested-datatype`.
- **`awsum-bench --snapshot` / `just benchmark-snapshot`: the no-simplify differential leg now runs under its own wider timeout, so a snapshot no longer fails spuriously on an unchanged compiler.** That leg — one unmeasured `SimplifyOff` run per backend against the cross-backend stdout anchor — shared the measured `--timeout`, but the Off pipeline is strictly slower than the On pipeline the budget is calibrated for, so a program near the boundary (`recursion-and-memory-safety` runs ~22s on CLR/WASM under On) timed out on the Off leg only — leaving an all-`ok` `bench.txt` while the run exited non-zero, intermittently under machine load. The Off leg now gets 3× the measured `--timeout` (a hang-guard, not a measurement): a genuinely hung backend still terminates, while ordinary Off-leg slowdown no longer reads as a behaviour divergence.
- **Partial application of a multi-argument built-in now compiles to working code on every backend instead of crashing the compiler.** `mulInt32 5` (one of two arguments) — let-bound, or passed to a higher-order function — type-checked but then aborted `build` / `run`: lowering left the under-saturated `CCall (CBuiltIn …)` callee in place, but a bare built-in callee is valid only when *saturated*, so codegen hit `arity mismatch` (LLVM/JS), an emitter-gate miss (JVM), or wrote an invalid artifact while reporting success (CLR `InvalidProgramException`, WASM trap). Because `awsum check` returned `OK`, the failure surfaced only at compile time — and silently on CLR/WASM. An under-saturated built-in call is now routed through the same `$bi$`-wrapper that already lifts a bare built-in used as a value, so the partial application becomes a partial application of a top-level function — the shape the closure passes (`Awsum.LowerClosures` / `saturateProgram`) already lower. A saturated built-in call still emits a direct `CBuiltIn` callee. Pinned by `builtin-as-value_partial-application`.
- **A point-free top-level alias of a compiler built-in now compiles to working code on every backend instead of crashing the compiler.** `f = BuiltIn.showInt32` — a renaming alias, where the bound name differs from the built-in's — type-checked but aborted `build` / `run`: lowering dropped every `x = BuiltIn.foo` declaration on the premise that a reference to `x` resolves to the built-in directly by name, which holds only when the alias name *equals* the built-in name — the convention the prelude's `foo = BuiltIn.foo` forwards all follow. For a renaming alias the dropped declaration left every reference to `f` resolving to a dangling variable, which downstream collapsed to an empty `case` (LLVM `use of undefined value`, JS `ReferenceError`, a WASM memory fault, a JVM emitter-gate miss, a CLR unknown-binder error); because `awsum check` returned `OK`, the failure surfaced only at compile time. Only the same-name form is now dropped; a renaming alias falls through to the alias-eta path and lowers exactly like the hand-written `f x = BuiltIn.showInt32 x` — identical stdout across all five backends. Pinned by `builtin-as-value_pointfree-alias`.

- **A file with no top-level declarations now parses, matching the grammar.** `docs/spec/grammar.ebnf` has always allowed zero top-level items (`{ TopItem , Terminator }`), but the parser required at least one (`P.some`, with `decls` typed `NonEmpty`), so an empty file, an imports-only file, or a module-comment-only file was rejected with `unexpected end of input` — an unfriendly diagnostic for the LSP "file is still being written" flow, where a new or half-typed buffer hits it before any real error exists. Such a file is now a valid empty module: `awsum check` and the LSP accept it silently (like any `main`-less library, the prelude included), and the absent entry point surfaces only when an executable is requested — `awsum build`/`run` report `Missing 'main' function` through the existing `requireMain` gate, exactly as for a `main`-less file that does have declarations. The top-of-file rule reserving the first position for a `{- … -}` module comment is unchanged (a leading `--` is still rejected there). Pinned by the `header-only-no-main` error snapshot and the `Typing.requireMain` parse-acceptance unit tests.

## [0.0.6] - 2026-06-03

### Added

- **`IO.Stdin.readAllBytes : IO Never (List UInt8)`** — CLI platform built-in that reads stdin to EOF as raw bytes, with no decode and no content-dependent failure (the result carries no error row). The companion to `readAllString` for input that isn't text, or text the host's argv decoder would mangle: stdin bytes reach the program verbatim on every backend. The per-target reader builds the prelude `List UInt8` directly from the captured bytes.
- **`byteToHexStringNoPrefix : UInt8 -> String`** (a per-target built-in) and **`bytesToHexStringNoPrefix : List UInt8 -> Either StringTooLong String`** (pure Awsum — a non-tail fold over `(++)`) in the prelude. Render a byte / byte list as lowercase, zero-padded, no-prefix hexadecimal (`0 → "00"`, `255 → "ff"`); the list form returns `Left StringTooLong` only if the joined result would exceed the string cap.
- **`InvalidUtf8`** type + **`showInvalidUtf8`** in the prelude — the byte-level decode failure `readAllString` reports for stdin bytes that are not well-formed UTF-8. Distinct from `UnpairedUtf16Surrogate` (a UTF-16-level failure of host-decoded argv): neither is a subset of the other.

### Changed

- **`IO.Stdin.readAll` is renamed `IO.Stdin.readAllString` and now decodes stdin as strict UTF-8 (RFC 3629); its error row changes from `(StringTooLong | UnpairedUtf16Surrogate)` to `(StringTooLong | InvalidUtf8)`.** Stdin is a raw byte stream the program owns end to end, so Awsum applies the full UTF-8 validity check itself rather than deferring to a host decoder. Any malformed sequence — overlong encoding, truncated multi-byte sequence, stray continuation byte, surrogate code point encoded in UTF-8, code point above U+10FFFF — is `Left InvalidUtf8`; a well-formed stream decodes to its `String` (`Left StringTooLong` past the 2^27 UTF-16 code-unit cap), and a leading UTF-8 BOM is kept verbatim as the ordinary scalar U+FEFF on every backend rather than silently stripped. `IO.Args.getArgs` is unchanged: argv is pre-decoded by the host, so its only failures remain `StringTooLong` and `UnpairedUtf16Surrogate`.

### Fixed

- **A string literal flowing into a structural sum is now injected (`CRow`), and a value already typed at a narrower row widens into a wider one correctly.** A string literal in a non-argument position whose type is a row — `val : (Int32 | String); val = "hi"`, or in a `let` RHS / `case`-arm / def body — lowered to a bare string (only the integer-literal arm injected), so the row-`case` mis-read it: crash on LLVM/JVM/CLR/WASM, `undefined` on JS. String literals now route through the same injection path the integer arm uses. This also closes the sub-row→wider-row case (`("x" : (String | Int32))` flowing into `(String | Int32 | Bool)`): row tags are per-label (FNV of the label name), so the widening is a pass-through once the leaf is injected — no separate coercion needed.
- **A row-unioning combinator applied to a continuation whose type can't be synthesised now injects the concrete error label.** `bindEither opA (const opB)` / `andThenEither (\_n -> opB) opA` — where the continuation is a partial application or a lambda — left one alternative of the result error row abstract, so the body-specialisation that injects the row tag was skipped and the `Left` payload reached the row-`case` un-tagged (crash on four backends, garbage on JS). The leftover labels are now recovered from the caller's expected result type before the body is re-lowered at concrete types; the argument-derived path the nested-combinator chains rely on is unchanged.
- **The Defunctionalize pass no longer hangs when a named top-level function is passed to a row-specialised combinator.** When the combinator's function-typed slot parameter shared a name with the passed function (e.g. a user `k` into a combinator whose continuation parameter is also `k`), `transformCall` re-resolved the same name through the closure environment forever — the compiler hung at the Core-to-Core stage with no diagnostic (typecheck passed). It now drops the name from the environment and dispatches the call as the top-level function it is.
- **Malformed UTF-8 on stdin now decodes — or is rejected — identically on every backend.** `IO.Stdin.readAll` previously routed stdin through whatever decode each host gave for free: a lenient U+FFFD-replacing decoder on JS / JVM / CLR, a byte-counting pass that copied invalid bytes verbatim on LLVM / WASM. Well-formed input agreed, but a malformed byte sequence diverged — one backend replaced, another truncated, another copied the bad bytes through. The renamed `readAllString` applies one strict decoder per target (hand-rolled RFC-3629 state machines on LLVM / WASM, the platform's fatal UTF-8 decoder on JVM / JS, a re-encode round-trip check on CLR), all pinned to the same well-formed-UTF-8 definition by a property test that compares all five against a Haskell oracle over arbitrary byte sequences.
- **A row-typed list built from literals mixing integer and string elements now compiles.** `Cons 1 (Cons 2 (Cons "x" Nil)) : List (Int32 | String)` was rejected with "integer literal without a known numeric type": `synthLabelType` under-approximated the element type as `String` — bare int literals contribute nothing to the synthesis, so a later string element alone fixed the element variable, and the ints were then lowered against a `String` element type. An argument that can't be synthesised but whose slot reaches the result now fails synthesis, so the declared element type propagates to every element.
- **Non-tail self-recursion under a structural-sum (row) case — or a tail row-injection — now compiles, in bounded stack on every backend.** A non-tail self-call inside a `(n : Int32)` row arm (`addInt32 n (sumRow t)`), or one whose result is injected into a row-typed return, was rejected by the stack-safety verifier (`UnsupportedRecursionShape`) even though the identical fold over a nominal type compiled and ran. `Awsum.Cps.goTail` now descends into `CRowCase` arms and tail `CRow` injections the way it already did for `CCase`/`CCon`, and the WASM tail emitter got the matching `CRowCase` arm. Closes a hole in "stack safety for any recursion shape".
- **An integer literal flowing into a structural sum is now injected (`CRow`) at lowering, closing a silent cross-target divergence.** A literal in a non-argument position whose type is a row — `(0 : Int32)` or bare `0` in an `(Int32 | String)` `case` arm, `let`, or function body — lowered to a bare integer: the typechecker accepted the implicit injection but lowering dropped the row tag, so a row-consumer misread the cell (LLVM/JVM/CLR crash, JS `undefined`). `EAscribe` now re-injects into the ambient row type, and a bare literal resolves against the row's unique int label — matching what argument position already did.
- **JVM methods larger than 32 KB now assemble correctly.** A branch spanning more than 32767 bytes — a large fused mutual-recursion loop's tail back-edge, or a `case` dispatch jumping over a >32 KB arm — had its signed-16-bit offset silently truncated, so the JVM rejected the class at load (`VerifyError`) even though the method was valid and well under the 64 KB ceiling; it ran on the other four backends and crashed only on the JVM. The assembler now widens far branches — `goto` → `goto_w`, conditionals via invert-and-`goto_w` with a synthesized skip frame. Methods under 32 KB are byte-identical to before; other backends are unaffected.
- **A function whose JVM bytecode would exceed the 65535-byte per-method limit (`code_length`, JVM Spec §4.7.3) is now refused at compile time instead of emitted as an invalid `.class`** that the JVM rejected only at load (`ClassFormatError`) — a program that built but crashed on the JVM while running fine on the other four backends. The build now fails with a diagnostic naming the method and its size. This is a per-target compile-time limit; capable backends aren't capped to match (see [docs/targets.md](docs/targets.md#per-target-compile-time-limits)). Reaching it takes a pathologically large single function; ordinary code is nowhere near it.
- **Implicit row injection now fires when a value reaches a wider structural-sum error type through a value-flow boundary, not only at a construction site.** Previously the row tag (`CRow`) was inserted only where a constructor was written directly at the row type (`Left ErrA : Either (String | ErrA) Int32`). A value that arrived already built — a `let`/def-body/`case`-arm variable, or the result of a row-unioning combinator (`bindEither`, `andThenEither`, `bindIO`, `andThenIO`) — kept its narrower representation, which the row-`case` then mis-read: wrong alternative on JS (the constructor tag surfaced as an `Int32`), out-of-bounds access on LLVM/JVM/CLR/WASM. Two parts: (1) an `EVar` used where a row is expected now routes through the existing injection (`let x : Either ErrA Int32 = … in x` at `Either (String | ErrA) Int32`); (2) a fully-applied call that widens an abstract error row `(e1 | e2)` into a concrete multi-alternative row is dispatched to a per-instantiation specialisation of the combinator, whose body is re-lowered at the concrete error types — the polymorphic original cannot inject, because its error types are still type variables when its body is lowered. Covers `Never` collapse, the primitive `String` as an alternative, one- and two-constructor nominal alternatives, idempotent `(e | e) ~ e` collapse, and multi-step chains. Programs that didn't hit the bug are unchanged — output stays identical on every backend.

Reason: Awsum has no catch-all on `case`, so each new platform-effect constructor added to `IO` would otherwise be a breaking change for any user program that wrote `case io of …`. The forbidden set is derived from the parsed prelude at compile time (auto-grows when `IO` gains a constructor); the diagnostic is uniform — `Name 'X' is reserved by the standard library and cannot be referenced from user code` — and the check runs before typecheck so violations appear ahead of any cascading "unbound name" errors. - **`IO.Stdin.readAll : IO (StringTooLong | UnpairedUtf16Surrogate) String`** — CLI platform built-in that reads stdin to EOF in the IO chain. Same error row as `IO.Args.getArgs` — decoding failures (length cap, unpaired UTF-16 surrogate) compose through `handleErrorIO`. Per-backend implementation reads raw bytes (`read(2)` on LLVM, `System.in.read` on JVM, `Console.OpenStandardInput` + `StreamReader` on CLR, WASI `fd_read` on WASM, `fs.readFileSync(0)` on JS) and decodes UTF-8 in the runtime, bypassing host argv decoders.
- **Doc comments.** A `--` line or `{- … -}` block touching the next top-level declaration with no blank line between becomes its docstring — no Haddock-style `-- |` / `{-| -}` prefix. Stacks freely across mixed `--`/`{- -}` chains; a blank line detaches the comment as a free-floating note. Content is markdown. `awsum format` normalises every attached doc to a single `{- … -}` block, preserving the author's line breaks. Reference: [docs/type-system.md](docs/type-system.md#comments-and-docstrings).
- **Hover (`textDocument/hover`) in `awsum lsp`.** Resolves the cursor against user + prelude decls together, so prelude names (`bindEither`, `mulInt32`, …) surface their docs the same as user-defined ones. Triggers on every name reference: top-level decl heads, `EVar` / `ECon` / `EBuiltIn` in expressions, `TyCon` in signatures and ascriptions, `PCon` in patterns. Constructor names that aren't a decl head fall through to the parent `TypeDecl`'s doc — hover on `Just` surfaces `Maybe`'s doc, which is where the constructor is documented. Hover `range` underlines the name itself, not the enclosing form. Markdown content; every LSP client (`awsum-vscode`, `awsum-zed`, `awsum-intellij`, `awsum-nvim`, `awsum-emacs`) picks it up with no client-side change.
- **Type information in hover.** The popup now ships the cursor's type alongside the doc — a fenced ` ```awsum ` code block on top, the doc below. Adds hover on /local binders/ that previously had nothing to show: function and lambda parameters, `case`-arm pattern variables, `do`-bind / `do`-let / `let`-bind names. Polymorphic references display both the declared scheme and the call-site-instantiated form, separated by an `Instantiated here:` line — e.g. `bindEither` inside `bindEither op1 (const op2)` shows `Either e1 a -> (a -> Either e2 b) -> Either (e1 | e2) b` alongside `Either ErrA Int32 -> (Int32 -> Either ErrB Int32) -> Either (ErrA | ErrB) Int32`. Monomorphic refs and locals show one block.
- **Balanced nested `{- … -}` capture.** The comment-capture path now balances nested block comments to match the space consumer; `{- {- -} -}` is one comment, not garbage from an early `-}`. An unterminated block at EOF fails with an explicit "unterminated block comment" diagnostic instead of an opaque parse error several lines below the cause.
- **`eqString : String -> String -> Bool`** in the prelude — equality on UTF-16 code-unit sequences.

### Changed

- **JS / JVM / CLR codegen: no redundant slot-null before a rebound loop parameter.** In a TCO'd self-tail-call (`CContinue`), a parameter whose old value is dropped and that the same continue immediately rebinds used to emit a slot null-out (`x = null` on JS, `aconst_null; astore` on JVM, `ldnull; starg` on CLR) right before the rebinding store. The store itself drops the old reference and nothing allocates between the two writes, so the null gained the GC nothing — it is now omitted on the three managed backends whenever the dropped parameter is rebound in that same continue. Drops on binders the continue does not rebind, and every drop at a value-producing tail, still null the slot; LLVM/WASM are untouched (their drop is a real free). No behaviour change — output stays identical on every backend.
- **JVM, CLR, and WASM codegen: text and binary output now share one instruction-IR.** Each of these backends used to lower Core to its target twice — once for the readable dump (`.j` / `.il` / `.wat`) and once for the shipped binary (`.class` / `.dll` / `.wasm`) — two independent passes that could silently disagree. Each now lowers Core once into a per-backend abstract instruction IR (`JvmInstr` / `CilInstr` / `WasmInstr`) whose operands are _symbolic_ — names and labels, never constant-pool indices, metadata tokens, or byte offsets — and the text renderer and the binary assembler are both total, decision-free projections of that single value; the assembler alone resolves the symbolic operands into concrete indices, tokens, branch offsets, and stack maps. So the text shown by `awsum asm` is a faithful view of the bytes that actually run, and the two cannot drift apart. Generated programs are unchanged — output stays identical on all five backends.
- **WASM codegen emits only the runtime helpers the program reaches.** The `.wasm` binary (and the `awsum asm -t wasm` dump) previously carried all ~42 runtime helpers at fixed indices regardless of use. They are now gated to the set reachable from the program — user code plus `_start`, closed over helper-to-helper calls — with every function index derived from that gated list. The user-code emitter calls helpers by name rather than by hardcoded index, so the gated text and the gated bytes resolve through one shared name→index map and cannot disagree on which helpers exist. No behaviour change — output stays identical on every backend; the `.wasm` is just smaller (a hello-world drops from 42 helpers to the handful it actually touches).
- **LLVM codegen emits only the runtime preamble the program uses.** External `declare`s and global constants that were previously always present are now gated next to their sole readers: `@snprintf` / `@.fmt_i32` / `@.fmt_u8` on the integer-`show` helpers, and `@strlen` / `@__free` / `@.cli_argc` / `@.cli_argv` — plus, on Windows, the whole argv-construction block (`GetCommandLineW` / `CommandLineToArgvW` / `WideCharToMultiByte` + `@.empty`) — on `IO.Args.getArgs`. `declare @printf` is dropped entirely (it had no call site). `_setmode` and the `v_main`/`runIO` handoff stay unconditional, as do `@__alloc` / `@__inc_ref` / `@__free_recursive` / `@memcpy`. No behaviour change — generated programs produce identical output on every backend; only dead preamble is removed (≈10.6k fewer lines across the snapshot `.ll` set).
- **`IO.Args.getArgs : IO (StringTooLong | UnpairedUtf16Surrogate) (List String)`.** Was `IO _ String` (a single argv[1]); now returns every command-line argument as a prelude `List String`. All-or-nothing error semantics: if any element fails to decode, the call returns `Left`. All five backends walk argv in full and agree element-for-element, including the empty-argv case (`Right Nil`) — LLVM stashes `argc`/`argv` at entry (converting the wide command line to UTF-8 on Windows) and WASM reads WASI `args_get` directly, both looping from `argc-1` down to 1.
- **`awsum run` argv via POSIX `--` separator; stdin inherits from the parent.** Was two mutually-exclusive flags — `--input TEXT` (singleton argv) and `--stdin` (read `awsum`'s own stdin, `T.stripEnd`, forward as `argv[1]`); both are gone. Now everything after `--` is forwarded as command-line arguments and read with `IO.Args.getArgs` as `List String` (no `--` → `Right Nil`); the child inherits `fd 0` directly, so `echo "data" | awsum run … FILE` and `awsum run … FILE < file` reach `IO.Stdin.readAll` verbatim (no buffering, no `T.stripEnd`, byte-exact across all five backends). The two channels are independent and can be used together: `echo "data" | awsum run … FILE -- arg1 arg2` delivers `["arg1", "arg2"]` to `getArgs` and `"data\n"` on stdin simultaneously.
- **Comments and layout no longer affect `awsum build` output or `awsum check` diagnostic text.** Synthetic binder names (`$do_e_N`, `$arg_N`, `$let_w_N`) are minted from a monotonic counter, and type-error messages show `expected x` rather than `expected x$3_12`.
- **Module comment header for `.aww` files.** A single optional `{- … -}` block at the top of a file is now treated as the module comment. Line comments (`-- …`) at the top of a file and multiple block comments in a row are rejected with a parse error: the language never silently attaches text above the first import or declaration. Concrete shapes:
  - **Before** — `{- header -}` glued directly to `import IO.Stdout` on the next line, or `-- header …` (often multi-line) before `import` / a top-level decl.
  - **After** — a single `{- header -}` block, then `import …` or the first declaration. The canonical form has one blank line between the header and the next line; the parser accepts both with and without the blank line, and `awsum format` normalises to the form with one. Other shapes (`-- header`, two `{- a -} {- b -}` in a row) are syntax errors.

  Leading comments on the first import are no longer accepted — they were ambiguous with module-comment material; subsequent imports may still carry leading comments (the "`-- import IO.X`" commented-out-import pattern between live imports). AST: `Program` gains a `moduleComment :: Maybe Text` field.

### Deprecated

### Removed

- **`awsum run --stdin` and `awsum run --input TEXT`** — superseded by stdin inheritance and the POSIX `--` separator (see Changed above). Migration: `echo … | awsum run … --stdin FILE` becomes `echo … | awsum run … FILE`; `awsum run … --stdin FILE < input.txt` becomes `awsum run … FILE < input.txt`; `awsum run --input "arg" … FILE` becomes `awsum run … FILE -- "arg"` — and multiple positional args after `--` are now possible (`-- arg1 arg2 …` → `List String`).

### Fixed

- **JVM verifier rejected a `CCase` in `CCall` argument position.** Two issues: branch-target offsets weren't shifted by the byte length of preceding sub-metas (StackMapTable frames landed before the actual targets), and the case declared an empty operand stack at its `if_icmpne` while the prior args still sat there. `CCall` now routes args through fresh locals when any arg contains a case, with the reserved save slots declared as `top` in the case's frame. Surface trigger: a `let` whose RHS is a `do`-block. LLVM/CLR/WASM/JS unaffected.
- **Top-level definition whose body is a bare lambda.** `f : Int32 -> Int32; f = \n -> n` (and curried / multi-param variants) used to be accepted by the typechecker but rejected at lowering with an internal `lambda has no expected type at lowering` error — the elaborator's zero-LHS path passed `Nothing` as the expected type, so `liftLambda` had no arrow to split. The elaborator now eta-contracts a top-level `ELam`-body into the `FunDef`'s LHS before lowering: `f = \n -> n` produces the same Core as `f n = n` (one `CFunDef`, no `$lam$N` helper). Curried forms (`\a -> \b -> body`) peel recursively. A non-lambda body that contains a nested `ELam` deeper down (e.g. in a `case` arm) now also receives the signature type as expected, so it goes through `liftLambda` correctly instead of dead-ending.
- **`UnusedTopLevel` false negative for short top-level names.** `freeNames` failed to subtract pattern-bound names from each `case`-alternative body, and the call-graph construction failed to subtract a top-level definition's own parameters. The combination silently masked any user-level top-level whose name happened to match a single-letter binder used inside a prelude case-alt (`Right a -> k a`, `Left e -> Left e`, …) or a prelude parameter (`(++) a b = …`). Both leaks are fixed; one-letter unused top-levels now warn correctly.
- **LLVM and WASM heap leak on every reference to a top-level `CValDef`.** The codegens were treating `CVar` references to top-level value definitions (e.g. `zero : Int32; zero = 0`) the same as borrowed-local CVars — emitting `__inc_ref` over the result. But each such reference lowers to `call @v_name()` which already allocates a fresh `+1` cell. The spurious inc left every referenced cell at refcount `1` forever, leaking once per reference in a hot loop. With the fix, peak RSS on `unused_case_binder_repeat` drops from 155 MiB to 2 MiB; on `mutual_three_way_repeat` from 1.5 GiB to 1.6 MiB. JVM/CLR/JS unaffected (host GC).
- **String property tests on Windows × JVM.** The 5 string-touching properties (`concat-left-identity`, `concat-right-identity`, `concat-associative`, `lengths-three-functions`, `concat-length-additive`) previously diverged on Windows × JVM because the JVM startup decoder (`sun.jnu.encoding`) mangled supplementary-plane characters in `argv[1]` before they reached user code. Property tests now feed input via `IO.Stdin.readAll`; stdin bypasses the startup decoder, so the round-trip is byte-clean on every host. The cross-backend assertion runs on every cell now — the Known Issue from 0.0.4 is closed.
- **LLVM Windows × MSVC CRT `\n` → `\r\n` translation on stdout.** The MSVC CRT opens fd 0/1/2 in text mode by default, so `write(1, …)` calls (used by the LLVM backend's `__print` runtime helper) silently doubled every `\n` into `\r\n` on output — breaking the cross-target "identical stdout" invariant. Latent since the LLVM Windows footer was added; only surfaced now that `IO.Stdin.readAll` lets `\n`-bearing input reach the program (`CommandLineToArgvW` had been stripping the same byte from argv). The Windows entry point now calls `_setmode(1, _O_BINARY)` and `_setmode(0, _O_BINARY)` before any IO, forcing stdin and stdout into binary mode regardless of CRT defaults. No effect on the POSIX footer (the call is Windows-only).
- **JVM/CLR binary assemblers emitted `__entryArgEither` unconditionally.** The text codegens (`Awsum.Codegen.{JVM,CLR}`) gate the `__entryArgEither` helper on `IO.Args.getArgs` ∨ `IO.Stdin.readAll`, but the binary assemblers (`JVM/Assemble.hs`, `CLR/Assemble.hs`) always emitted the method — so the `.class` / `.dll` carried a method the `.j` / `.il` snapshot omitted (its only callers, `__getArgs` / `__stdinReadAll`, are themselves gated; `Main` never calls it). The binary assemblers now gate it on the same predicate. On CLR the gate is applied in lockstep to both the method table and `allNames` (which assigns `MethodDef` tokens), so user/`Main` tokens stay aligned. No behaviour change — the method was dead when absent; runtime output is identical on every backend, and the text snapshots are unchanged.

  - Shadowing is now a compile error at every binding site (was a silent behaviour before).

- **Prelude** (implicitly imported — no `import` needed)
  - Bundled prelude compiled into the binary via `file-embed`; user programs see its declarations without an `import` line. Unused entries are dropped by reachability-based tree-shake from `main`.
  - Types: `Bool` (`True` | `False`), `Either a b` (`Left` | `Right`), `Maybe a` (`Just` | `Nothing`), `Unit`, `UnderflowError`, `OverflowError`.
  - Bool operators: `not`, `and`, `or`.
  - String concat: `(++) : String -> String -> String`.
  - Show functions: `showInt32`, `showUInt8`, `showUnderflowError`, `showOverflowError`.
  - Honest arithmetic: `predInt32` / `succInt32 : Int32 -> Either {Underflow,Overflow}Error Int32`; same shape for `UInt8`. The `Either` wrapping is mandatory — overflow/underflow cannot silently wrap.
  - Equality: `eqInt32 : Int32 -> Int32 -> Bool`, `eqUInt8 : UInt8 -> UInt8 -> Bool`.
  - `BuiltIn.foo` reserved syntax — per-target compiler implementation escape hatch behind prelude-visible names.

- **Backends** (four new targets)
  - **LLVM** — native binary via Clang (LLVM 15+ for opaque-pointer support).
  - **JVM** — Java 7+ bytecode generated directly (no Jasmin / javac dependency); ships a built-in `.class` assembler (`Awsum.Codegen.JVM.Assemble`).
  - **CLR** — .NET 9+ `.dll` generated directly as a PE file (no ilasm / csc).
  - **WASM** — WebAssembly with WASI preview 1 (tested against wasmtime); ships a WAT assembler for `.wasm` binaries.
  - Cross-backend equivalence is a compiler invariant: every successful test asserts identical stdout across LLVM, JVM, CLR, WASM, JS, and Lua.

- **Stack-safe recursion**
  - Three-pass Core-to-Core pipeline that normalises every recursion shape into a loop on every backend:
    - `Awsum.Scc` — merges mutual recursion into self-recursion via Tarjan SCC + sum-tag dispatch.
    - `Awsum.Cps` — rewrites non-tail self-recursion into tail-self through a defunctionalised K chain.
    - `Awsum.Tco` — folds the remaining self-tail-calls into `CLoop` / `CContinue`.
  - Self, mutual, and non-tail recursion all run in bounded stack on all six backends — including JVM and JS, which have no native cross-method tail calls.
  - 1 000 000-iteration stress tests per recursion shape per backend.
  - `Awsum.StackSafety` rejects mutually-recursive top-level values (no fixed point) with a dedicated diagnostic before the merge pass runs.

- **Platform effects**
  - `--program-type cli` flag introduced; mandatory for any command that goes through the typechecker.
  - Qualified effect names (`IO.Stdout.print : String -> IOUnit`) — a CLI-program platform effect requiring both `--program-type cli` and `import IO.Stdout`.
  - `Awsum.Program.platformTable` dispatch ready to host `ProgramBrowser` / `ProgramModule` without touching existing modules.

- **Compiler**
  - Source positions (`SrcSpan`) tracked through the entire pipeline — error messages now include line and column numbers with clickable terminal links.
  - `awsum check --json` outputs structured diagnostics with `severity` (`"error"` | `"warning"`) and `fixes` (array of `{title, edits}`) fields. Parse-time, type-time, and warning diagnostics share one shape.
  - `awsum check --strict` escalates warnings to a non-zero exit code for CI.
  - Warnings with rename-to-`_name` quick-fixes: `UnusedParameter`, `UnusedTopLevel` (unreachable from `main`, reports only the source-SCC roots), `UnusedTypeParameter`.
  - New error family for the underscore convention: `ReferencingIgnored`, `ReferencingIgnoredTypeVar`, `ReferencingIgnoredConstructor`, `UnnamedType`, `UnnamedConstructor`, `UnnamedTypeParameter`, `DuplicateTypeParameter`.
  - Unreachable case arms produce an error (`UnreachableCase`).
  - Per-identifier source spans on function params, type parameters, constructor declarations, and constructor patterns — enables precise caret placement and minimal-edit quick-fixes.
  - New module `Awsum.Diagnostic` centralises severity/fix/edit types and JSON encoding.
  - Reachability-based tree-shake from `main` over all top-level Core decls (user, prelude, generated constructor wrappers) — unused prelude entries never reach codegen.

- **CLI**
  - `awsum core FILE --program-type cli` — print elaborated/lowered Core IR.
  - `awsum asm FILE -t {jvm|clr|wasm}` — print target assembly text (Jasmin-like / CIL / WAT).
  - `awsum symbols FILE --json` — emit an LSP-style `DocumentSymbol` array for Outline view and workspace symbol search.
  - `awsum run --input TEXT` / `awsum run --stdin` for passing input to `main`.

- **Documentation**
  - `docs/prelude.md` — Prelude + BuiltIn architecture design doc.
  - `docs/recursion.md` — stack-safe recursion pipeline walkthrough.
  - `docs/targets.md` — per-backend implementation details.
  - `docs/platform-version-policy.md` — which runtime versions each backend targets and why.

- **Testing**
  - Cross-backend equivalence tests: each `test/sources/successful/NAME/` is compiled to all six backends and asserted to produce identical stdout.
  - Golden snapshots per pipeline stage (AST, Core IR, formatted source, per-backend output text, runtime output).
  - Auto-detection of tests — adding a new test program in `test/sources/successful/` is enough; no registration required.
  - Error snapshot tests: `test/sources/errors/` with JSON diagnostics as the golden.
