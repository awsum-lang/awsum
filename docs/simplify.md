# Simplify — the Core simplifier

`Awsum.Simplify` is a Core-to-Core pass: a fixpoint of local rewrites (copy-propagation, dead-`let` elimination, single-use binder inlining, case-of-known-constructor, constant folding, and non-recursive function inlining). It is the home in the pipeline for inlining and, later, supercompilation — the place a whole class of optimisations live, rather than a one-off peephole in a single backend.

Its first concrete job is to remove the verbose single-use bindings that case lowering produces — `const v = s[1]; return [3, v]` becomes `return [3, s[1]]` — but it is built as the general optimiser, not as that cleanup alone.

> Status: the full rule set has landed — single-use case-binder inlining into `CProj`, case-of-known-constructor (nominal and row forms), case over a top-level constant, identical-arms collapse, case-of-case fusion with join points (and case-of-join above a residual join), identity reconstruction, integer constant folding, non-recursive function inlining, and the `let` family (dead-`let`, single-use-`let` inlining, copy-propagation, known-projection, `let`-from-scrutinee floating) — verified by the test suite (identical stdout across all five backends), the property layer (the `fnInline-`, `constFold-`, `caseOfCase-` and `reuseSharing-differential` oracles), the no-simplify differential, and the benchmark golden files. Function inlining is the first `CLet` producer, which is what brought known-projection and the `CLet` codegen lowering live. This document records the design and the rationale behind the substrate choice.

## Substrate: case-binders + `CLet` / `CProj` (coexistence, not full ANF)

Core keeps its `CCase` / `CRowCase` arm binders, exactly as it always has. Two nodes are added:

- `CLet n rhs body` — `let n = rhs in body`.
- `CProj n i` — slot `i` of the constructor cell bound to variable `n` (slot 0 is the tag; fields are slots 1.., the layout `CReuse` writes). A leaf, like `CVar`.

The unifying rewrite is: a case-arm binder used exactly once is inlined into a `CProj` at its single use, and dropped from the arm's binder list:

```
case s of K [v] -> C[v]      -- v used once
  ==>
case s of K [] -> C[CProj s i]
```

`CLet` carries the rest: it binds a non-variable scrutinee before such an inline when needed, and it binds inlined function arguments and known-constructor fields (so a value used more than once is shared, never duplicated).

## Why coexistence, not full ANF

A stricter design — *full ANF* — was considered and rejected: make case arms bind nothing, so that **every** binding is a `let` and **every** field read is a `CProj` (`case s of K {} -> let v = proj s i in C[v]`).

Both designs reach the same end: the single-use cleanup, case-of-known-constructor, function inlining, and a substrate fit for supercompilation. The difference is cost versus uniformity:

- Full ANF would **relocate all field-binding** out of case arms into `let` + `CProj` — touching lowering, `Lifetime`, `Reuse`, and the case-handling of all five codegens — to buy a single conceptual property (one binding form instead of two). It changes no observable outcome.
- GHC Core — the proven substrate for a production inliner/simplifier, and for experimental supercompilation — **keeps case-binders**. It materialises the field projection in its backend, where a register holding a field is free. Coexistence mirrors that and adds only `CProj` (to express the field-inlining in Core, which is what lets the cleanup happen at all) plus `CLet`.
- "Perfect means there's nothing left to cut away": coexistence is strictly less machinery for the same result, so it is the cut. Lowering is not touched at all; `Lifetime` and `Reuse` are *augmented* (handle `CProj` / `CLet`) rather than rewritten; the codegens *add* a slot-load for `CProj` and a bind for `CLet` rather than rewriting how they handle case arms.

**Full ANF stays a possible future tightening.** If a concrete need appears — say a supercompiler that genuinely wants one uniform binding form — the migration is additive, not a redesign: the `CLet` / `CProj` nodes and the `Simplify` pass are already in place, so it reduces to changing lowering to emit `let` + projection and dropping the arm binders. Until such a need is real, the extra uniformity is not worth the pipeline-wide rewrite.

## Load-bearing invariants

- **`Simplify` runs exactly once — after `Tco`, before `Lifetime`.** Both bounds are load-bearing. *Never after the memory passes:* `Lifetime` places `CDrop`s and `Reuse` rewrites linear-scrutinee reconstruction into in-place `CReuse`; they are the last word over the final code shape, and a later `Simplify` would have to respect already-placed drops and formed `CReuse` cells. *Never earlier either:* the single-use inline is sound only on final-shape Core. Its same-arity carve-out reasons about the reconstruction cells it can see — run before `Cps` / `Scc`, those passes introduce same-arity cells *afterwards* (continuation chains, argument packs), `Reuse` rewrites one of them in place, and the manufactured `CProj` beside it reads the overwritten slots. Observed, not hypothetical: a trial post-`Defunctionalize` run point inlined a `Cons` arm's binders, `Cps` then captured the whole cell where it previously captured one field, `Reuse` turned that continuation cell into `CReuse` on the scrutinee — JVM type confusion, WASM out-of-bounds, LLVM garbage bytes. Earlier run points restricted to case-of-known-constructor *are* sound, but were measured to change no final artifact across the entire test corpus, so the pipeline keeps the single point; they can return when a rule with a real early effect lands (constant folding ahead of the recursion passes is the candidate).

- **Inlining a case-binder into `CProj` requires a local or parameter variable scrutinee.** The rewrite above fires only when `s` is a variable bound to a local or a parameter; a non-variable scrutinee is `let`-bound first. If the scrutinee binding were inlined away, `Reuse` would lose the linear scrutinee it matches on, and hot loops that today reuse a cell in place would start re-allocating — a memory and time regression. A **top-level value definition** is excluded for a different reason: on LLVM/WASM a `CValDef` reference lowers to a getter *call* that allocates a fresh cell on every reference, so a `CProj` over it would re-invoke the getter — the case match and the projection would read two different cells, and the second one leaks (never reclaimed). The carve-out is the same boundary `borrowedSource` already draws on LLVM (a `CValDef` is a fresh source, not a borrow). Pinned by `simplify_no-inline-over-valdef-scrutinee`: stdout is identical across backends (the getter is deterministic), so only the Core/codegen snapshot — one getter call, no `CProj` over the value-def — catches a regression.

- **The same-arity carve-out applies only to reuse-eligible scrutinees.** An arm that rebuilds a cell of its own arity keeps its binders extracted so `Reuse` can rewrite the reconstruction into an in-place `CReuse` — but that rewrite is reachable only where `Lifetime` can place a scrut drop *inside* the arm, and it places one for exactly two shapes: a *parameter* of the enclosing function, dropped at each `CContinue` (`scrutReuseEligible` in `Awsum.Lifetime`), and a *binder whose sole use is the scrutinee of an inner nominal case*, whose drop sinks into that case's arms (`soleScrutineeUse` — the shared predicate; this is what makes the continuation cells of `$scc$`-merged CPS functions reusable, see [memory-management.md](memory-management.md)). Any other scrutinee — a multi-use binder, every `CRowCase` (`Reuse` descends through rows without matching) — gets no protection because there is nothing to protect: their single-use binders inline like everywhere else, and identical-arm collapses are not blocked. Soundness does not rest on this prediction — `Reuse`'s own scrut-use gate (`binderUsedIn`) refuses to rewrite a cell beside any surviving read of it, and a Simplify↔Lifetime disagreement (a rewrite changing a use count mid-fixpoint) degrades to a missed reuse, never a miscompile: a premature inline leaves a `CProj` name-use that falsifies `soleScrutineeUse` on the Lifetime side, so no drop sinks and no reuse fires. Extending where `Lifetime` places in-arm scrut drops must extend the eligibility in the same change. How the fired rewrite then takes its cell is the `ReuseMode` split (unconditional for compiler-minted packs/continuations, checked or alloc-backed for user data — [memory-management.md](memory-management.md)); and "kept extracted" is a Core-level statement — on the managed backends the store scheduler reads most of those binders straight off the cell and skips their extraction at emission (`Awsum.Codegen.ReuseSchedule`). Pinned by `simplify_same-arity-gate-param-only` (a *twice-used* binder scrutinee's binders inline to `CProj` despite the same-arity rebuild, while a parameter scrutinee keeps its binders and `CReuse` fires in the loop) and `memory_nested-reuse` (a sole-use binder keeps its binders and the nested `CReuse` pair fires).

- **`CProj` is an owning projection — the same semantics as today's case-arm field binder.** On the reference-counted backends (LLVM, WASM) it loads slot `i` and increments its refcount, exactly as the case-extract does; on the managed backends (JVM, CLR, JS) it is a plain index and the host GC handles the rest. So a field projected into a new constructor is *moved out* of the scrutinee with the same refcount discipline as before, and the scrutinee's recursive drop stays balanced. A field used more than once stays a binder (single move); only single-use binders are inlined (still a single move).

- **A binder is not inlined when the scrutinee name is shadowed inside the arm.** Lowering mints *deterministic* pattern-binder names (`__p0`, `__pa0`, …) so sibling arms of one case share names and `mergeAlts` can fuse them — but the same counter restarts per nesting level, so two nested `Just (Tuple2 …)` patterns both bind `__p0`. With binders kept, each is extracted in its own scope before the inner `__p0` shadows it; inlining an outer binder into `CProj __p0 i` would push its read down past the inner `__p0`, reading the inner cell's field instead (`Tuple3 a b c` silently became `Tuple3 b b c`). So an arm whose scrutinee name is rebound anywhere in its body is left untouched — the dual of the capture-avoidance the substitution already does for the binder's own name. (This is also why the cross-backend check below is not sufficient on its own.)

- **Case-of-known-constructor substitutes only what cannot duplicate work.** `case (CCon t fs) of … (t, vs, body) …` collapses to `body[vs := fs]` (rows likewise, dropping the `CRow` wrapper) — but only when every binder passes the gates: a binder used once takes any field (evaluated once, at the same or a conditionally lower frequency — `CLoop` only wraps whole function bodies, so no use site is hotter than the scrutinee was); a binder used more than once takes only a plain non-value-def variable (a literal re-evaluates into a fresh cell per use on LLVM/WASM, a value-def reference is a getter call); a binder used as the *name* of a `CProj`/`CReuse` blocks the rewrite (those positions need a name, not an expression); a substituted field's free names must not be re-bound inside the body (the deterministic `__p0` names again). Substitution is simultaneous, so a field spelled like another binder cannot be captured. The rewrite runs *before* the arm body is simplified — the reverse order would let the single-use inline manufacture `CProj binder` names that block it. `Reuse` loses nothing: the scrutinee cell is never built at all. Pinned by `simplify_case-of-known-constructor`, `simplify_rowcase-of-known-row` (collapse) and `simplify_no-known-con-on-shared-field` (gate holds).

- **A case whose arms all return the same body collapses to that body — the dispatch decides nothing.** One arm qualifies trivially (`case u of Unit -> e`, the residue of every `andThenIO (\_u -> …)` chain), identical arms over any dispatch fold (`and x False` / `or x True` inline to exactly this shape, so boolean absorbing elements disappear), and the rule composes with the flow-sensitive dead-arm pruning: a case whose *surviving* arms agree collapses after the unconstructed constructor's arm is gone. A pure scrutinee is dropped with its computation — the same dead-computation stance as dead-`let` (divergence is deliberately not preserved for dead code); an effectful one keeps evaluating and only the dispatch goes, the call sequenced before the common body through a dead `CLet` that the dead-`let` rule's own effect gate preserves. The four platform-effect primitives (`internalStdoutPrint`, the argv/stdin readers) are the only calls in Core whose evaluation is observable — they survive lowering solely inside `runIO`'s walker, whose print arm is literally `case (print s) of Unit -> …`: the print stays, the single-arm dispatch around it disappears. The same `effectfulIn` predicate hard-gates every unused-position drop (dead-`let`, unused inline arguments, unbound known-constructor fields) that assumed purity latently — an effectful expression is never dropped. Remaining gates: the common body must not read any arm's binders (two syntactically equal bodies reading their own arms' binders bind *different* fields — the deterministic `__p0` names repeat across arms); a *field-binding* arm rebuilding a cell of its own arity keeps the case when the scrutinee is reuse-eligible (`Reuse` territory, the same carve-out — and the same `scrutReuseEligible` boundary — as the projection inline) — binder-less arms are exempt, since their "arity" is zero and any nullary constructor in the body would match it, blocking exactly the absorbing elements and the `-> True` extractors for a reuse win of one tag store; an empty case (uninhabited scrutinee) stays. Pinned by `simplify_case-single-arm`, `simplify_case-identical-arms` (nominal + row), `simplify_case-identical-arms-pruned` (the pruning composition — the program folds to its constant) and `simplify_case-identical-arms-gate-holds` (a multi-use binder and a same-arity rebuild both hold; the rebuild lives in a loop casing its own parameter — the eligible shape — and `Reuse` rewrites it in place).

- **An identity reconstruction is its scrutinee.** An arm that rebuilds the very cell it matched — the same tag, every binder back in its own slot (`case x of K v1 v2 -> … K v1 v2 …`), the nullary `True -> True` / `Leaf -> Leaf` included, and the row re-injection `(a : A) -> (a : (A | B))` likewise — reduces the reconstruction to `CVar x`. This is the do-desugar's `Left e -> Left e` residue, which Cps threads into every `$apply` dispatcher; reduced, a continue argument becomes a parameter self-pass, arms that turn syntactically equal fold via the identical-arms collapse, and the vanished reconstruction releases the same-arity carve-out on the arm's other binders. Skipped when the scrutinee or a binder is re-bound inside the body (the deterministic `__p0` names again). Pinned by the regenerated corpus (`closure_box`'s dispatcher arm is the canonical instance: `k = k[1]; continue`, no cell built at all).

- **Case-of-case fuses through the same resolution machinery, with join points for the arms that stay.** A case whose scrutinee is another case resolves the outer case against every inner arm whose body is a literal constructor tree (or a registered top-level constant) — the `knownArm` gates unchanged — and mints a `CJoin`/`CJump` pair for the rest: the outer case exists once as the join body, and each unresolved arm jumps to it with its value. Gates: at least one arm must resolve (fusing without a single collapse only restructures); the selected outer arm's own free names must not collide with the inner arm's binders, checked *before* substitution — afterwards the substituted fields legitimately mention them; a static resolution materialises a copy of its selected outer arm — every copy with its binders freshened, so a `CLet` an earlier inline left in the arm never declares one name at two sites — and the copy count is the selection count *plus one whenever a join exists* (the join body retains the whole outer case) — more than one copy must be small and case-free, or the arm demotes to the jump side: the fusion's termination measure is the case-node count, which every firing strictly decreases, and an outer arm carrying a `do`-chain continuation would otherwise double per bind level (the int32_parse 2^12 blowup — substituted copy + join-body copy at every bind; a demotion creates the jump that re-prices the remaining single selections, so the gate runs to its boolean fixpoint in two passes); and an unresolved arm whose tails transfer control cannot become a jump argument — a transfer is not a value — so that fusion is not performed. Outer arms carrying a `CContinue` move freely: a loop transfer only occurs when the fused case sits in loop-tail position, where every backend walks the minted join's body with its full tail emitter. An outer arm jumping to an *enclosing join* does not: it occurs when the fused case sits in that join's inner tails — which the join, and hence the minted one, may reach in expression position — and a minted join whose body jumps outward is the one shape the expression-position emitters do not lower (the boundary `consumeJoin` already draws), so the jump-minting side declines the fusion (`ocJumpsOutward`); the all-static side stays free, its resolved copies landing at the tails the originals occupied. The broader gate that excluded every transfer-carrying arm existed for the expansion adapter, which lifted join bodies into top-level functions, and went with it. A case whose scrutinee is a *residual join* consumes it through the same resolution machinery (case-of-join): every value tail of the join — its body's and its inner expression's, transfers passing through untouched — must be a literal tree whose selected consumer arm passes the same gates plus the strict pricing, and the resolved arms then replace the tails in place; all-or-nothing, because a partial push would strand the leftover tails on a fresh consumer join whose body jumps outward — the one shape the expression-position emitters do not lower (their join bodies are values; only the statement walks route arbitrary transfers). A declined consumer stays a case over the join node, the form it already had. This is what lets a tower keep collapsing above its first residual join — the level above folds into the join's tails, and the next level sees a join again. The node flows out of the pass: the post-Simplify tree-shake walks it, `Lifetime` places drops around it (join parameters follow the *function-parameter* discipline — no `CDrop` wrap, the value-tail dec is codegen's, exactly as for any function — and since drops always wrap whole scopes while a join body's free names are always bound above the `CJoin`, no drop ever sits between a jump and the body it transfers to), and `Reuse` recurses through it without ever matching a pattern across the join boundary. Every backend lowers the node natively as a real intra-function jump — LLVM: the join body is a labelled block, the parameters travel through prologue-allocated slots (`mem2reg` turns the store/load pairs into phis), a jump incs its borrowed arguments and releases what accumulated since the node exactly as a `CContinue` does, and the body releases the parameters value-tail with the move carve-out, the function-parameter discipline they follow; WASM mirrors the same discipline through structured control flow — two void blocks, the value through a per-nesting-level result local, the parameters in a dedicated locals region, the branch depths on the `CContinue` counter; JS is a labelled block named after the join with the body laid right after it — the parameters are uninitialised `let`s at the node, a jump assigns them directly, nulls the function parameters dropped since the node and `break`s, bypass tails `return` past the body, and an expression-position join runs the same lowering inside an immediately-invoked arrow; the JVM is a `goto` to the labelled body with the parameters in the `CLet` named-slot region — `top` in every StackMapTable frame inside the inner expression, `Object` from the body label on — jump arguments evaluated one at a time straight into the slots, bypass values `goto` an after-label carrying the one-item-stack merge frame, and the node gated to empty-stack positions exactly like a multi-arm case; the CLR is a `br` to the labelled body with the parameters in scratch slots reserved at the node — no frame tables exist, so the construct only needs its incoming edges to agree, and the bypass values merge at an after-label one above the construct's base depth exactly as the case emitter's join already does inside cell fields. The expansion adapter that bridged the staged migration — every join lambda-lifted into a top-level `$join` function, every jump a full-arity `CCall` — is gone with the last backend's native lowering; the no-simplify differential's Off leg never sees a join either way. Pinned by `simplify_case-of-case-fuse` (literal tower → a single case), `simplify_case-of-case-join` (mixed arms → a `CJoin` in `core.txt`, a native jump or a lifted `$join` in each backend's `compiled.*`), `simplify_case-of-case-join-live` (the join body references an enclosing binder — the live set is non-empty, the leak/use-after-free-sensitive shape on the reference-counted backends), `simplify_case-of-case-shared-arm` (duplication gate passes), `simplify_case-of-case-gate-holds` (duplication gate demotes every arm, nothing collapses, no fusion), `simplify_case-of-case-continuation-gate` (a `do`-chain whose binds carry the continuation in their outer arm — the join-body pricing demotes them, Core stays linear), `simplify_case-of-case-continue-arm` (a loop dispatch whose outer arm recurses — the join body carries the `CContinue` and runs once per iteration), `simplify_case-of-join` (a tower above a residual join folds into its tails — one `CJoin` left), `simplify_case-of-join-gate-holds` (case-carrying consumer arms — all-or-nothing declines, the consumer stays a live case over the join) and the `caseOfCase-differential` property (random boolean towers over a runtime seed, both pipeline modes × five backends against a Haskell oracle — its eighth generated case caught the live-variable capture of an inlined `$join` callee before any hand-written test did); `stress-300_calls` — a 300-deep chain of `and`-towers that used to exhaust the inliner's budget every 42 levels — collapses to `print "True"`.

- **A case over a top-level constant collapses through the same gates.** A scrutinee naming a `CValDef` whose final simplified body is a constructor tree built entirely of constructors and literals resolves to that tree and the collapse above fires (a plain-variable body chases to its target's registered constant, so alias chains fold too). Only constant trees register: on JVM/CLR/JS a value definition is evaluated once at startup and read per reference, so a substituted field that carried computation would re-run it per execution of the collapse site — a frequency the literal-scrutinee argument above doesn't cover; a constant tree carries no work, has no free names (the capture guard is vacuous), and its materialisation is bounded by the inliner's always-inline size policy. On LLVM/WASM, where a value-definition reference is a getter *call* allocating a fresh cell per reference, the collapse strictly removes allocations — and it removes getter references rather than projecting over them, so the value-def-scrutinee leak boundary above is untouched. Declarations are visited dependency-first (the same order the inliner uses; the call-graph edges include plain variable references), so a constant's body is final before any reader is simplified. Pinned by `simplify_case-over-valdef-constant` (collapse + alias) and `simplify_no-collapse-over-computed-valdef` (gate holds); `stress-300_defs` — 300 `Bool` constants folded by `and` — collapses to `print "True"`, its 3.4 MB of generated JS down to the runtime shell.

- **Constant folding builds the exact value the runtime helper would build — never a compile error.** A call to an integer built-in over literal operands (`add`/`sub`/`mul`/`succ`/`pred`/`eq` on `Int32`/`UInt8`/`UInt32`, plus `negInt32`) is evaluated at compile time into the same `Either` cell the helper returns: `addInt32 2147483647 1` folds to `Left (OverflowError : (UnderflowError | OverflowError))` — the signed add/sub/mul family's row wrapper included, with the same FNV-1a label tags the codegen helpers embed — and `succUInt8 255` to a bare `Left OverflowError`. Errors are values; a literal that overflows is a valid program computing a `Left`, and the fold preserves exactly that. The folded constructor then feeds case-of-known-constructor, so a whole case chain over literal arithmetic collapses to the branch the runtime would have taken. String built-ins are deliberately *not* folded yet: a folded result string sits outside the source-literal length cap, and a concatenation over 21845 UTF-16 code units cannot be carried by a single JVM `CONSTANT_Utf8_info` entry — string folding needs that analysis first.

- **Function inlining runs only at the final pre-`Lifetime` point, on non-recursive callees, and never nests a `CLoop`.** A callee qualifies when its body has no `CLoop` / `CContinue` / self-call (post-`Tco` that is exactly "non-recursive"), it is never referenced outside a callee position, and it is either small (`inlineAlwaysMaxSize`) or called from exactly one site (`inlineSingleSiteMaxSize` — the definition then falls to the tree-shake, so the rewrite never grows the program). The post-`Tco` call graph is a DAG — `Scc` fused every cycle, `StackSafety` verified, `Tco` folded self-tail-calls into loops — so inlining along it cannot create recursion, and declarations are processed callees-first so a callee's registered body is final (and its size honest) by the time its callers are considered. Per argument the gates mirror case-of-known-constructor exactly: an unused parameter drops its argument unevaluated, one use substitutes any *pure* argument (an effectful one stays `let`-bound — the single use may sit inside a case arm, where the effect would run conditionally), multiple uses substitute only a duplicable variable and otherwise share the argument through a `CLet`; a parameter used as a `CProj` name is renamed to the argument variable, or `let`-bound when the argument is not a plain variable or is spelled like another parameter (which also legalises a value-definition argument — the getter runs once and the projections read the local). Every binder of the inlined body is freshened (`$inl<k>$<stem>`), and the parameter renames run *before* the argument substitution — a substituted argument may mention a caller variable spelled like a parameter, which a rename over the already-substituted tree would capture (the prelude's `and a b` inlined where the second argument mentions the caller's own `a` was the observed instance) — so capture is impossible in both directions and the per-name slot maps of the stack backends stay unambiguous. This keeps the stack-safety guarantees the recursion passes (`Scc` / `Cps` / `Tco`) establish intact — an inliner that duplicated a recursive body or nested loops could break them.

- **An expression-position `case` yields an owned value on the reference-counted backends.** A call boundary turns a borrowed argument into an owned result for free — the caller's arg-inc travels out through the callee's move carve-out. Inlining erases the boundary: `Box f -> f v` becomes `case b of Box f -> …` whose arm tail is a borrowed binder, and that value then flows into a transfer position (a cell field, a call argument, a `let` binding, an outer scrutinee) which would store it un-inc'd while the binder's `CDrop` frees it — a use-after-free the snapshot suite caught on the closure-stress program the day inlining landed. So LLVM and WASM emit an inc at every expression-position arm tail whose value is a borrow (fresh sources and move-inc'd drop tails pass through), making every expression's value owned except a bare variable — the same classification `borrowedSource` / `isHeapBorrow` implement, now move-aware (a `CDrop n` whose body returns `n` already owns its value) and `CLet`-transparent. The managed backends need nothing. This also closes the latent pre-inlining instance: a surface `f (case b of True -> x; False -> y)` with borrowed `x` / `y` had the same hole.

- **`Simplify` is an optimisation, not a lowering — the pipeline stays correct with the pass disabled.** A library-level, test-only switch (`SimplifyOff`; the `awsum` CLI has no such flag) skips the pass and its re-shake, leaving exactly the pipeline as it stood before `Simplify` landed, and the differential gates below run it continuously. The invariant cuts both ways: a rule that changes observable behaviour fails the gates, and so does a downstream pass or codegen that comes to *depend* on `Simplify` having run — the fix then belongs in the codegen, not in the pass.

## Rules

Run to a fixpoint at the single run point above:

copy-propagation · dead-`let` elimination · single-use case-binder → `CProj` · single-use `let` inlining · `let`-from-scrutinee floating · case-of-known-constructor (literal scrutinee or top-level constant; and known-projection of a let-bound constructor's field) · case-of-case fusion (static resolution per arm + join points, expanded to top-level `$join` functions at the end of the pass) · constant folding · function inlining (non-recursive, size-bounded).

Not changing the call graph does not make a rule position-independent — the single-use inline is call-graph-safe yet final-shape-only (the invariant above). If interleaved run points return, each carries the subset of rules whose soundness argument holds at that position, not the full pass. Function inlining is additionally confined to the final run, with the restrictions above.

## Verifying it does not regress

`Simplify` is a refactor of generated code, not of behaviour: the same program produces identical stdout on all five backends before and after. Three test layers check this, and **all are needed**:

- **Snapshot suite** — asserts the five backends produce *identical* stdout for each program. It catches a backend *disagreeing*, but not a *uniform* miscompile: `Simplify` runs on Core, before codegen, so a wrong rewrite makes all five backends agree on the *same wrong* answer and sails through. The scrutinee-shadow bug above did exactly that.
- **Property suite** — feeds generated inputs through every backend *and* an independent Haskell oracle, in both pipeline modes (with and without `Simplify`). This is the layer that catches "all backends agree but the answer is wrong", and the one that caught the shadow bug (`parseInput` returning `Tuple3 b b c`). A Core-level pass like `Simplify` must clear the property suite, not just the snapshots. Constant folding gets its own shape of property (`constFold-differential`): the generator emits the *program*, not the input — operands fed through argv/stdin stay runtime values and never fold, so only source literals put the rule under test. Each generated program carries every (operation, outcome) pair with random magnitudes; the `SimplifyOn` compile evaluates them in `constFold`, the `SimplifyOff` twin routes the same literals to the runtime helpers, and both must match the Haskell oracle on all five backends — `fold == runtime` on the exact overflow/underflow boundaries.
- **No-simplify differential** — `just test-no-simplify` recompiles the whole successful corpus with the pass disabled and asserts each backend's stdout still equals the committed goldens, and `just benchmark-snapshot` adds one unmeasured no-simplify run per backend against its stdout anchor. The oracle here is the runtime itself: `runtime(simplify(core)) == runtime(core)` holds on every corpus program with no hand-written expectation, and every future rule lands against it — constant folding, in particular, is pinned to *the runtime helpers as they actually behave* (the off-mode run computes the same literals at runtime), not to a third reimplementation of overflow semantics. The off-mode runs also keep the codegens exercised on raw, unsimplified Core shapes, so a shape `Simplify` happens to clean up can't quietly become one no backend handles.

A *leak* is a third failure mode that neither stdout suite sees: a rewrite can keep stdout byte-identical yet allocate a cell that is never reclaimed on the reference-counted backends (the value-def-scrutinee `CProj` above did exactly that — the getter ran twice, one result orphaned). The guard is reading the `compiled.*` / `core.txt` snapshot diff itself — a doubled `@v_…()` call, or a `CProj` over a name that should have been extracted, shows up there even when every backend prints the same thing.

Performance is a fourth check: the median-benchmark golden files record per-backend wall time and peak RSS as `median (min–max)` cells. Peak RSS is deterministic on compute-bound programs (`tree_sum`) but **bimodal** on allocation-heavy ones (`list_reverse`, `gc_pressure` swing ~4.5 MiB between two arena-chunk modes on a *fixed* binary), so a bare median can flip modes and read as a phantom ±4.5 MiB regression — the (min–max) band is what tells that flip from a real shift: overlapping bands are noise; disjoint *tight* bands are a step (compiler change or environment mode) worth re-measuring before/after in one session. It is a signal for large shifts (e.g. `Reuse` ceasing to fire), not a tight gate. Snapshot before a change, snapshot after, read the `git diff`.
