         coexists with the user top-level `cont` below.

         Every Core pass that resolves a bare reference against the global
         declaration table (defunctionalisation, closure lowering) must treat
         that local `cont` as the `IOGetArgs` continuation, not as the
         top-level function. Before the fix it resolved to the top-level,
         dropped the continuation's captures, and emitted a dangling closure;
         `runIO` then called a non-function and every backend failed
         (`v_cont is not a function` on JS, a runtime trap on LLVM, a hang on
         the JVM). The uniquify-locals pass renames the colliding local away
         before defunctionalisation, so all five backends agree.
