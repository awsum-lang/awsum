           sumTree (Node l v r) acc = sumTree r (sumTree l (acc + v))

         Cps allocates one K_1 per Node visited to carry the outer call's
         remaining arg ('r') forward across the inner call's return, and
         the K_1 apply arm tail-calls '$cps$sumTree' — the same '$cps$f' ⇄
         '$apply$f' cycle as 'tree_mirror_repeat' but with one K per Node
         instead of two and no fresh Node allocation per iter. Pure K-cell
         churn under the post-Cps SCC merge.

         Shape: a left-spine tree of depth 10_000 is summed 1000 times.
         Each sumTree call walks the spine producing 10_000 K_1 allocations;
         the K cells are short-lived (one per call stack frame, released as
         the chain unwinds). Total allocation: 10⁷ K cells.

         Output: '10000' (sum of 10_000 ones). The tree itself is built once
         and shared across all 1000 reps, so steady-state live set is one
         tree (~10_000 Node cells) + the current K chain (≤ 10_000 cells). "
